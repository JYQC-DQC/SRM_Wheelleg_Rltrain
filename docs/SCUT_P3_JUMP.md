# SCUT 参考车 P3：无梁预训与标准梁验收

当前入口用 `config/reference/scut_p3.yaml`。这是参考车仿真实验配方，不适用于上大实车。旧混训 run 的数值不代表新任务成绩。

## 实心梁

依据《RoboMaster 2027 机甲大师超级对抗赛比赛规则手册 V1.0.0（20261015）》印刷页 59、§4.4.2 图 4-38：梁前沿距道路入口 1.350 m，沿行进方向长 350 mm，车道净宽 800 mm；道路表面高出场地基准 G 200 mm，梁顶高出**道路表面** 270 mm。把路面设为局部 `z=0`，用 `0.350 × 0.800 × 0.270 m` 的实心盒模拟车道内顶面投影；盒中心为 `(1.525, 0, 0.135) m`。不挖洞、不建护栏实体，不复现道路高度台差或裁判卡。MuJoCo 用 `python -m tools.build_tunnel_model` 生成同一尺寸的标准模型。

## 顺序

1. `p3-jump` 无梁。每回合固定为零速或正向行进，默认各 50%；80% 回合在 2–5 s 模拟一次按键，20% 不按。速度和机身上升目标是参考车试验范围，不是已验证能力。先分别确认原地和带速跳能离地、落稳，并从 `jump_motion.npz` 查看在足够净空下的**连续前进距离**，不能用起跳 `vx` 或单个峰值替代。
2. 用同一平地 checkpoint 直接评 `p3-tunnel`。所有用例有标准梁，按速度、早／晚按键分组，记录离地、通过、触地、落稳，不混入原地样本。位置用于仿真脚本模拟操作手按键，不是部署触发方案，不把测距交给 Actor。
3. 直接评测已有足够成功率和按键窗口就不另训。否则用 `--initialize-from` 仅继承平地 Actor 开新 `p3-tunnel` run，不能完整 resume 旧混训。顶面落地、碰撞、绕行、首轮过早触地均失败。30 mm 净空、50 mm 后沿裕量、1 s 落稳是训练验收约定；轮底和刚体原点只是近似，完整净空仍需按目标资产验证。表 5-27 的裁判卡窗口另测。

## 奖惩

借鉴复旦的支撑期蹬伸、华南虎的起跳／收腿分相：蹬伸以有轮支撑的向上速度为主，目标速度以上不额外发分；蹬伸和下降准备都用单边腿长引导，0.28 m 以下只按短缺折减，达到后再伸不减分，不追踪腿长随时间的轨迹。0.28 m 是参考车试验值，不是关节限位。本次保留原 0.25 s 下蹲阶段；确认离地后不再给下蹲引导。关闭按腾空时长发奖、空中奖金、轮速对齐罚和未经实际冲击测量的髋力矩代理罚。平地目标按最低能力评分：顶点低于目标减 0.01 m，仍可获落稳奖但不计入升档；达到下限且落稳后，超高不降顶点奖，也不挡升档，仍须满足带速门槛。评测另报 `jump_overshot`（确认离地且超目标 0.03 m）和 `jump_height_in_band`（达标且未超高），避免把跳得更高和精确控高混作同一个指标。过梁不按机身升高量判失败或发顶点奖。空中速度跟踪降权，触地后恢复跟踪，落稳和速度恢复分开看；碰梁沿用一次事件失败罚，不再叠加顶面持续罚。

**无梁跳跃计时**：按键后 1.2 s 内须确认离地；确认后不设单独的滞空时限，仍受训练回合、评测时长与安全终止约束。首次有效触地后 5.0 s 内必须完成双轮连续落稳 1.0 s（这 1.0 s 包含在 5.0 s 里）。任一轮离地或姿态不合格仍清零连续落稳计时，后续触地不延长截止时间；提前落稳就立即结算。Actor 的阶段时钟仍按 1.2 s 缩放，越梁流程及硬失败判据不变。新配方不改变已启动的训练；切换时新开 run、只继承 Actor。

## 分组跳高课程与稠密引导

- **共享 Actor，课程独立**：用每回合固定的速度目标分原地／带速，不按瞬时速度重新分组。各组独立维护八档采样、当前最高档的窗口及每档引导退火，并各自保存在 checkpoint。机身上升目标依次为 4、9.25、14.5、19.75、25、30、35、40 cm；仅解锁第一档时只采第一档，之后 60% 采当前最高档，40% 在已开放的低档间均分。40 cm 是仿真课程目标，不是已验证跳高能力。窗口达到至少 500 次已触发的已结算尝试时判定一次（同一批新样本一并计入）；达到 70% 就升一档，否则留在原档。无论是否通过都开始新窗口，不累计前窗失败。已开放的低档仍混采，但不计入升档。带速跳在确认离地时还要达到目标前向速度的 70%，否则仍可获落稳奖，但不给跳高达成奖、不视为该档成功。未按键对照和按键前失败不进跳高样本。TensorBoard 分别查看 `Jump/stationary/*` 和 `Jump/moving/*`：`window_count` 是当前窗口样本数，`levelN/last_window_success_rate` 是该档上一次已结算窗口的成功率（尚未结算则为 0）。旧累计课程或旧奖励配方的 checkpoint 用 `--initialize-from` 迁移 Actor，不沿用旧课程成功计数。
- **不是全稀疏，稀疏的是结果反馈**：下蹲、蹬伸、收腿、准备本来就逐拍计分，但最终顶点奖和落稳奖要等触地并落稳 1 s 才结算。只在无梁阶段增加 `jump_height_progress`，确认离地后对本次新达到的归一化机身高度按增量发奖，最高到目标高度；一次跳最多 +0.5，独立按本组本档的引导系数退火。保持高度、下降后再次爬到已付高度、超高、无有效离地都不加分。越梁阶段不使用该项，也不恢复按腾空时长付费。
- **下一轮观察**：与 `jump_height_progress=0` 对照，固定初始 Actor、配方其余项和种子；按原地／带速看确认离地率、带速合格率、跳高达标率和落稳率。若只涨离地、落稳反而掉，先减小进展权重，不继续加腾空奖励。这里的 0.5 和 70% 是参考车实验起值，尚未用 PPO 结果验证。

## 运行入口

使用准备好的 SCUT `robot.yaml`；下列 `<...>` 替换为已有文件。先完成基线验证或按现有流程显式记录基线覆盖。

```text
python -m isaac.scripts.train --task p3-jump --robot <robot.yaml> --policy config/reference/scut_p3.yaml --run-name p3_flat --initialize-from <landing.pt> --headless
python -m isaac.scripts.evaluate --task p3-tunnel --robot <robot.yaml> --policy config/reference/scut_p3.yaml --checkpoint <p3_flat.pt> --output runs/p3_beam_eval --headless
python -m isaac.scripts.train --task p3-tunnel --robot <robot.yaml> --policy config/reference/scut_p3.yaml --run-name p3_beam --initialize-from <p3_flat.pt> --headless
```
