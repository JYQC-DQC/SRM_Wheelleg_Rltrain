# P1-landing 首次落地奖励设计

当前实现：`wheelleg/landing_rewards.py`，接入 `isaac/wheelleg_tasks/env.py`，仅 `p1-landing` 训练回合生效。
2026-11-12 第二版（在 f1fe0a3 上修改）。只跑了 CPU 单元测试；未在 Isaac 中运行、未训练、未实机验证。

## 事件生命周期

只有 reset 真正采样的空中出生开启事件，每回合最多一次：腾空 → 缓冲 → 稳定 → 结算。
结果一确定就立即结算并关闭事件，不再等到首次接触后固定 3 s。

| 阶段 | 进入条件 | 地面项 | 落地项 |
|---|---|---|---|
| 腾空 | 出生后、首次任意刚体 >3N 之前 | 速度/高度跟踪、竖直速度、站定、俯仰负罚关闭；`flat_roll`/`flat_pitch` 正奖励、roll 负罚、角速度保留 | 轮心居中、轮速对准，只罚不奖 |
| 缓冲 | 首次接触后，直到双轮连续支撑 0.1 s 或触地后 0.5 s（先到者） | 速度/高度跟踪、竖直速度、站定关闭；俯仰负罚恢复 | 进展奖励 |
| 稳定 | 缓冲结束；只进入一次，弹跳不重开 | 全部恢复 | 进展奖励 |

| 结算 | 时刻 | 金额 |
|---|---|---:|
| 成功 | 首次连续 0.5 s 达标（双轮持续支撑、无非轮触地、倾角/角速度/竖直速度/高度误差在阈值内） | +1.5 |
| 非轮触地 | 发生当步 | −1 |
| 物理终止、数值异常 | 发生当步 | −1（另有原终止 −4） |
| 不稳定 | 首次接触后 3 s 仍未成功 | −1 |
| 无接触 | 出生 2 s 未触地 | −1 |
| 外生 timeout | 发生当步 | 0，不计入成功率分母 |

进展奖励沿用 Q=exp(−0.25×Σ(误差/阈值)²)，只付历史最高值的增量，每事件最多 +0.75。
正奖励合计 2.25 仍小于终止代价 4。

## 为什么这样改（相对 f1fe0a3）

- 结算时机：γ=0.995、100 Hz 时 3 s 后的奖励只剩 0.995^300≈0.22。成功/失败改为在决定它的动作附近立即支付。
  成功后若再失稳，由原有稠密项和终止代价处理；诊断仍按 3 s 窗口末独立评估。
- 缓冲期：上一版首次 3N 轻触后立即恢复全部跟踪/高度项，单轮擦地时就要求正常高度和速度。
  现在给一次性过渡，截止时间从首次接触算，弹跳和轻触都不能延长；非轮触地立即结算，不享受过渡。
- 空中引导：上一版删掉旧的 +20/s 零力矩、+10/s 轮心居中和 −10 轮速匹配后，空中只剩总额 0.1 的力矩代价，
  俯仰和腿姿都没有直接信号。现在恢复姿态正奖励，并加两个只罚不奖的腾空项（完全达标时为 0）。
  这两项自身不奖励推迟触地；但空中仍有姿态正奖励和地面项豁免，整体是否偏向晚触地要看
  `Landing/first_contact_s/mean` 是否随训练增大、是否出现主动收腿。
  - 轮心居中：航向系（只含 yaw）轮心 x，exp(−x²/0.02) 的两轮均值，权重 4/s。SCUT V14/env_cfg.py:1617-1623, 1657 为正奖励 10。
  - 轮速对准：轮缘线速度对准航向系真实前向地速，exp(−均方误差/1.0)，权重 2/s。这是减少触地滑移的近似目标，
    未考虑每侧轮心随腿摆动的速度、机身转动和轮子朝向，不保证无滑移。
    Actor 只看到指令，多数出生里指令≈地速。若用指令作目标，独立出生样本（如指令 0、实际 2 m/s）会被教成刹车。
- 出生速度：Actor 没有机身速度观测，上一版出生 vx 与指令独立，落地前无法预知地速。
  现在 80% 空中出生 vx=指令+N(0, 0.3) m/s（像开下台阶），20% 仍在 ±2.5 m/s 内独立采样；
  出生时直接把指令设为（限幅后的）目标值，并冻结速度和高度指令直到首次接触后 3 s 窗口结束。
  提前成功和事件失败（如非轮触地）都不解冻，只有出生 2 s 未触地或回合结束时提前解冻；
  与诊断窗口同一步结束，窗口末稳定率和碰撞后恢复统计都不混入对新指令的响应。
  出生线速度改为只按 yaw 旋转（SCUT wheelbipe25_v3/env.py:5186-5207），倾角不再把前向速度转成竖直速度；此项对所有 P1 空中出生生效。
- Critic：奖励依赖事件历史，critic 追加 9 维事件状态：进行中、腾空、缓冲、触地后时间/窗口、已稳定时间/0.5 s、
  进展最高值、触地前出生年龄/2 s、缓冲期连续支撑时间/0.1 s、指令冻结中。均在 [0, 1]。
  landing 的 `state_space` 相应为 81+9=90；评测环境补 0 保持维度。Actor 35 维合同不变。

## 环境集成

- 数值安全：环境数值检查除关节/机身速度外，还检查根位置、姿态四元数和关节位置是否有限（对所有任务）。
  非有限时与速度异常同样立即终止、当步普通奖励置 0；落地事件另付有限的 −1。
- `landing_progress`、`landing_outcome` 登记为 `EVENT_TERMS`：它们是每事件总额，不受持续项 `reward_clip` 限幅。
- 指令课程衡量“在指令下行驶”，腾空和缓冲步不计入回合平均误差（与这两段关闭跟踪奖励一致）。
  全程都在这两段内的短回合不参与课程判定。
- 高度门控：landing 在腾空/缓冲段置 1，之后按实际高度误差计算，不再用旧 airborne 状态机的退出停留时间。
  旧状态机在 landing 中只保留两项功能：`air_joint_limits` 罚项和腾空倾角终止阈值（`airborne_tilt_rad`）。

## 空中出生高度课程

指令课程不看落地结果，所以另加一个只管出生高度的课程（`stages.landing.air_height_curriculum`，只对 p1-landing 训练）。

- 出生高度偏移在 [0.12, 当前上限] 均匀采样，上限按 0.20 → 0.24 → 0.28 → 0.32 → 0.36 → 0.42 m 逐级放开；低处始终保留在分布里。
  每档只加 4 cm（最后 6 cm），新一档和上一档难度差小。早期分档是 0.20/0.28/0.35/0.42。
- 只统计最新一档（上一级上限到当前上限）出生、已结算的事件。成功指奖励状态机的首次恢复，
  分母是成功+失败，外生 timeout 不算；诊断模块按约定仍不影响训练。
- 每满 1024 个事件为一个不重叠窗口，成功率 ≥ 0.8 则升一级，不降级。升级前出生、之后结算的事件落在旧档，不计入新窗口。
- 4096 环境、空中出生概率 0.4 时每轮约 40 次空中出生，最高一档占 20–100%，一个窗口约 25–130 轮。数值是设计初值。
- 评测、stairs、recovery 仍用完整的 0.12–0.42 m。课程状态存进 checkpoint，并记录上限高度 `upper_m`：
  改分档后续训按高度恢复，不会因为档位编号变了而悄悄降高度；没有 `upper_m` 的旧 checkpoint 按旧分档换算。
  未满的窗口只在这一档的下限 `lower_m` 和上限都没变时保留；任一变化（例如上限仍是 0.28 但分档细化后
  统计区间从 0.20-0.28 变成 0.24-0.28）就丢弃，指令课程的落地门槛计数也一起丢弃。
  没有该课程状态的 landing checkpoint 不能单独 `--resume`；配合 `--command-fraction` 重启课程时可以。
- `train.py --resume ... --restart-air-height`：续训时把高度课程退回第一档（0.20 m），日志打印 `AIR_HEIGHT_RESET`。
  和 `--command-fraction 0.4` 一起用即从 0.4 速度、最低高度重新循序推进。
- 日志：`Curriculum/air_height_max_m`（当前上限）、`Curriculum/air_height_band_success_rate`（上一个窗口的成功率）。
  `LandingReward/first_recovery_rate` 统计全部高度，会高于最新一档的成功率。

## 指令课程的落地门槛

指令越大，80% 的空中出生飞得越快，所以速度课程不能跑在落地前面（`stages.landing.command_curriculum_landing_gate`）。

- p1-landing 训练中，指令课程的一个窗口（4096 个结束的回合）要同时满足：回合通过率 ≥ 0.8（原条件），
  且同一窗口内结算的、出生在当前最高一档高度的落地事件首次恢复率 ≥ 0.8、事件数 ≥ 256，才升级。
  外生 timeout 不算。早期版本统计全部高度，低处容易的落地让速度从 0.4 升到 0.7，而高度一直停在 0.28 m。
- 两个课程现在看同一档的成功率，形成顺序推进：高度升级后新一档更难，指令课程暂停，等新一档也过 0.8；
  高度课程不反过来看速度，因为抬高出生高度不会让平地跟踪变难。高度到 0.42 m 后，门槛看 0.36-0.42 m 这档。
- 高度升级的那一步，指令窗口里已累计的落地计数（全是旧档）被清空，之后只用新一档的事件重新凑满 256 个。
- flat/stairs/recovery 的指令课程不变，checkpoint 格式也不变。landing 的门槛计数存进 checkpoint。
- 日志 `Curriculum/command_landing_gate_rate`：上一个指令窗口内的落地成功率。`Curriculum/pass_rate` 仍是速度那一侧。

## 导轮分级、落地窗口触地倍率、伸腿引导（2026-11-12）

旧训练日志：落地失败几乎全是非轮触地，髋力矩每次顾到 40 Nm，空中轮速引导只实现了约 69% 的最大罚分。

- 导轮（`guide_body_regex`）不再等同碰撞。事件未结束时，每次新的导轮接触都取该导轮刚体接触前一个物理子步（2 ms）
  的下落速度（含机身俯仰带来的部分）：≥ 1.0 m/s（几乎没缓冲）按落地失败（`failure/guide_impact`），
  前面轻蹭过一次后再重撞也一样失败；否则不算失败，每次扣 0.5 × 速度/1.0（`landing_guide_contact`，事件总额不限幅），
  之后仍可成功。没有“每事件只扣一次”的历史状态，所以 critic 不需要新特征。机身、云台、腿连杆触地仍是失败。
  导轮触地那一步不算双轮支撑，稳定计时会清零。速度取的是导轮刚体的竖直速度，仍是缓冲程度的近似指标。
  “一次接触”指一个环境在某个 2 ms 采样里出现新的导轮接触；同一采样里几个导轮同时碰地，按其中最快的分级、
  只扣一次，`guide_contacts` 也只加 1，不是按导轮个数计。
  边界情况：导轮速度非有限时事件记为数值异常（`failure/invalid`），不当作 0 速度；
  reset 后第一个物理采样就碰导轮（没有接触前的速度样本）按硬撞处理，单独计数 `guide_contact_without_prior_sample`。
- 落地窗口（出生到首次触地后 3 s，即指令冻结期）内 `undesired_contact` ×8，约 -32/s，按策略步计，
  每个触地的步至少 0.32。SCUT 在 airborne 状态用 ×25。两个目标分开：短暂蹭地允许恢复成功；
  压着导轮支撑重罚，0.1 s 就约 -3.2，会超过失败代价 1；导轮仍在物理终止名单里，累计 0.4 s 会终止。
  所以“导轮接触比失败便宜”只对单次接触的扣分成立，不对总成本成立。
- 空中伸腿：每条腿各自计算低于 0.28 m 的缺口再取平均（一条长腿不能补偿另一条），按缺口/0.1 m 罚，
  封顶 -4/s，只罚不奖。只管触地前，任一轮接触后两腿一起关闭，不约束接触后的压缩。SRM 配置里目标为 null。
  可能改善缓冲行程，也可能让触地姿态更硬，是实验初值，要看动作。
- 空中轮速对准权重 2→8：实验选择。轮速误差大也可能来自预转时间短、目标对 Actor 不可见或轮力矩受限。
- 诊断新增 `Landing/touched/<刚体>`（该刚体在事件中碰过地的事件数）、`Landing/first_nonwheel/<刚体>`（第一个碰地的非轮刚体）、
  `guide_only_contact`、`hard_contact`；奖励侧新增 `guide_contacts`、`guide_impact_speed_m_s/mean`，
  以及严格对照 `first_recovery_no_guide_rate`（成功且全程未碰导轮，与导轮分级前的口径可比）。
  诊断的 clean/window_end 口径不变，任何非轮（含导轮）触地仍不算 clean。
  导轮放宽会直接抬高课程成功率：判断动作是否真的变稳，要看严格对照指标，并在固定速度难度下比较。
- critic 合同不变（9 维事件特征），可从当前 landing 检查点 `--resume`。阈值和权重均为设计初值。
- 恢复系数未改：反弹阈值 0.5 m/s，落地 1.6-2.4 m/s 会触发反弹，但 e≤0.2 时刚体反弹高度 ≤ e²h ≈ 1.2 cm、
  返还能量 ≤ 4%（均匀分布平均约 1.3%），影响小。

## 日志

两条成功率含义不同，不会自然相等：

| 指标 | 含义 | 分母 |
|---|---|---|
| `LandingReward/first_recovery_rate` | 首次达到连续 0.5 s 稳定（奖励口径）；不说明之后是否保持 | 成功+失败，不含外生 timeout |
| `Landing/window_end_stable_rate` | 首次接触后 3 s 窗口末仍连续稳定且全程无非轮触地，不要求对称触地 | 全部结算，含中断 |

指令在整个窗口内冻结，窗口末的失稳不会来自新指令。`clean_success_rate` 另要求两轮触地差 ≤50 ms，
作为质量指标，不作为随机出生姿态下的硬门槛。
`LandingReward/*` 还有 births、success、`failure/{collision,terminated,invalid,no_contact,unstable}`、
neutral_timeout、pending、success_time_s/mean（首次接触到成功）。
奖励与诊断的阈值必须相等，配置校验不一致时报错。

## 未解决的边界

- 没有冲击力、冲量或触地前轮缘滑移约束；当前更接近“落地后恢复”，不等于“柔和缓冲”。
  先看 `Landing/*_peak_n` 和恢复时间，再决定是否加约束，不填未经标定的力阈值。
- p1-stairs / p1-recovery / P3 仍使用旧空中奖励（零力矩 +20/s、轮心 +10/s、轮速 −10、腾空倍率）。
- 权重 4/2、缓冲 0.1/0.5 s、80% / 0.3 m/s 都是设计初值。若首批长期全失败，先查 reset/接触/计时，再调权重。
- 成功在首次稳定 0.5 s 时支付，之后翻倒不撤回 +1.5（普通奖励和终止仍生效）。是否合适看
  `window_end_stable_rate` 与 `first_recovery_rate` 的差距。
- 上述环境集成（奖励汇总、课程累计、高度门控）没有 CPU 测试：`tests/test_numerical_safety.py` 的 env 桩已过时，
  修复前只能靠代码审查和 Isaac 冒烟。

## 运行与验证

critic 维度和 checkpoint 合同（`landing_event_features`）已变：旧 landing checkpoint 不能 `--resume`，
用 `--initialize-from` 只继承 Actor。需重新运行 `tools.prepare_scut` 或同步两份 P1 配置中的新键。

CPU 测试 `tests/test_landing_rewards.py`：成功只付一次且在首次稳定时、碰撞立即失败且之后不再付钱、
弹跳不能延长缓冲、终止/数值异常/外生 timeout 的结算、无接触截止、地面出生不开事件、重复 tick 不改变结果、
指令冻结在提前成功和碰撞失败后都保持到窗口末、回合结束或无接触截止时解冻、腾空项非正且触地后关闭、
轮速目标是真实地速而非指令、事件总额不被限幅、姿态非有限判为数值异常、
critic 特征全程有界、奖励/诊断阈值不一致与缺键时报错。
这些是状态机数值测试，不代表 Isaac 接触时序、GPU 训练或实车已经通过。
