# P1 landing 首次落地训练诊断（2026-11-12）

## 范围

仅 `p1-landing` 且非 evaluation 时创建 FirstLanding。评测分支、P3跳跃事件、P1其他阶段不改。
唯一奖励修改：两份P1配置的 `stages.landing.reward_overrides.track_height_wide=1.5`。
flat退火、stairs/recovery权重、空中轮速项、1秒物理终止宽限期及课程升级规则不改。
此事件模块不输出奖励、不修改终止、不进入Actor/critic。

## 生命周期

1. 从 reset 真正采样的 air 掩码开启事件，地面出生不开启。若状态库覆盖了该初态，则不再算空中出生事件。
2. 按 `_sim_step_counter` 的差值计出生年龄，不使用 rsl_rl 可随机初始化的 episode_length_buf。
3. 从第一个新的物理采样开始记录当前法向接触力。首次任何刚体超过3N时锁定首次接触时间和刚体掩码。
   同一2ms采样多刚体触地全部记录；不虚构采样间先后顺序。已有历史最大力仍用于原奖励，诊断不使用历史最大值计时。
4. 独立记录左右轮第一次超过3N的时间。出生2秒仍无任何接触则结束，归为no_contact。
5. 首次接触后观察3秒，弹跳/再次离地也属于这一事件，不重开。不会在首次短暂稳定时提前宣布成功。
6. 窗口末尾要求至少连续0.5秒：每次物理采样双轮各>20N、无非轮触地；策略步姿态/速度/高度误差达标。
7. 事件结束后保持关闭直到下一次 reset；回合后面的再次跳起、碰撞或翻倒属于整回合指标，不追溯改写首次落地结果。
8. 事件中若实际terminated、timeout、数值异常或外部显式reset，则中断结算，绝不补记成功。

配置 `stages.landing.landing_diagnostics` 必填，缺失报错。阈值是诊断设计值，不是已验证的机械安全界限：

| 条件 | 默认值 |
|---|---|
| 首次接触/非轮触地法向力 | 3N |
| 双轮支撑力 | 每轮20N |
| 首次接触等待上限 | 出生后2s |
| 接触后观察窗口 | 3s |
| 窗口末连续稳定 | 0.5s |
| 左右轮首次触地时间差 | ≤0.05s |
| roll/pitch绝对值 | 各≤10° |
| roll/pitch角速度绝对值 | 各≤0.5rad/s |
| 世界系垂直速度绝对值 | ≤0.2m/s |
| 对当前高度参考的误差 | ≤0.05m |

稳定条件不要求vx/wz跟踪：落地姿态恢复与行驶指令跟踪分开，后者继续由原整回合课程统计。
双轮支撑和无接触在物理采样中检查，姿态/速度/高度按100Hz策略步检查。

## 互斥结果与日志

每个已结算事件恰好属于以下一类：

- `clean_success`：窗口末稳定，整个事件无非轮触地，双轮首次触地时间差达标。
- `collision_recovered`：窗口末稳定，但期间发生过非轮触地（优先于不对称分类）。
- `asymmetric_recovered`：窗口末稳定且无非轮触地，但双轮触地时间差不达标。
- `unstable`：有接触，但完整窗口末仍未连续稳定。
- `no_contact`：等到出生接触截止时间仍未触地。
- `aborted`：终止、提前timeout、数值异常或外部reset打断事件。

`Landing/air_births`、`resolved` 是每轮新增/结算次数，`pending`是当前未完成事件数；
正常运行时累计 births = 累计 resolved + pending。重启日志是新的诊断统计段，事件状态不随checkpoint恢复。
`clean_success_rate`的分母是该轮resolved，包含中断事件；没有结算事件时不写成功率点，而不是写0。
长窗口应按成功数/结算数加权，不平均各轮成功率；`failure_rate=1-clean_success_rate`表示未满足完整诊断标准，
包含“碰撞后恢复”及中断，不能解释成全是摔倒。
`early_timeout`单独计数，避免init_at_random_ep_len造成的首批短回合被误读为落地动作退步。

`Landing/first_body/<USD刚体名>`记录已结算事件的首次接触刚体次数，同时触地可使各身体次数之和超过接触事件数。
`first_contact_events`、`both_wheels_touched`、`nonwheel_contact`、`recovered_once`给出相应分母。
触地时间差/恢复时间、左右轮法向力峰值、非轮法向力峰值、髋命令力矩绝对峰值、接触后倾角峰值各写count/mean/max。
恢复时间是首次接触到首次完成连续0.5秒稳定的时间；若之后又失稳，保留这个时间，但最终结果仍为unstable。
缺失恢复时间/轮触地时间不填0，相关count为0时不写mean/max。无接触或数值失败次数仍明确保留。
`Landing/height_wide_weight`显示当前有效1.5权重。

法向力不是含摩擦的总接触力；髋力矩是软件下发值，不是结构冲击或实测电机力矩；
力峰值不等于冲量，本版没有添加安全冲击阈值，也没有声称clean_success等于机械安全验收。

## 出生类型与奖励

分出生类型统计诊断是合理的：地面样本没有执行“从高处落地”任务，不应混入成功率分母。
但若以后仅按不可观测的出生标签给相同碰撞不同惩罚，会引入隐藏上下文，增加学习/价值估计难度。
更合适的是保留所有回合通用的接触/姿态约束，额外的落地项由实际离地→接触事件和局部窗口触发，
而非终身按air-reset标签区别对待。应先看当前诊断，再批准新增奖励及对应事件范围。
本次不新增落地扣分，地面出生和空中出生原有接触惩罚均保留；仅landing全体样本宽核高度权重统一为1.5。

## 运行与验证边界

更新实际启动使用的policy快照/重新prepare_scut，旧run配置不会自动变化。继续使用 `--task p1-landing`，
无需新任务或开关。宽核权重有变，按仓库约定建议 `--initialize-from` 继承Actor，不把旧critic/优化器原样恢复。
旧checkpoint仍可按原配置运行；跨阶段Actor加载遵循当前历史估计器合同，不改35维单帧语义。

接触API依据 `runs/api_reference/contact_sensor_data.py:77-99`；物理步次序依据
`runs/api_reference/direct_env.py:370-393`。每个物理tick只采一次：下一子步之前读上一子步，末尾在_get_dones读最后子步。
不受1秒物理终止宽限期屏蔽，也不依赖airborne状态机及时进入。
按此前约定不运行测试/训练/评测；只做源码检查和静态检查。传感接触时序、阈值、GPU运行开销尚未在Isaac验证。
