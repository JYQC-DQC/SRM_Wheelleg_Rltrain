## 1. 先弄清三件事

### 1.1 策略输出什么，固件里跑什么环
| 通道 | 策略输出 | 固件里的闭环（500 Hz，H7 上算） |
|---|---|---|
| 4 个髋电机 | 位置目标 `q_ref = q_default + 0.5·a`，再按限位裁剪 | `τ = Kp·(q_ref − q) − Kd·q̇`，MIT 模式只发力矩（帧里 kp = kd = 0） |
| 2 个轮电机 | 速度目标 `ω_ref = 10·a`，再按上限裁剪 | `τ = Kd_w·(ω_ref − ω)`，换算成电流发给 C620 |

- 每个电机只有这一层 PD，没有积分，不串级。队内框架原有的角度环、速度环 PID 不用。
- 这层 PD 和训练里的 `motor_torque()`（`wheelleg/tensor_ops.py`）是同一个公式。辨识时也用它，回放时才能一一对应。

### 1.2 Kp/Kd 不是辨识出来的
- 辨识的对象是 armature、摩擦、阻尼、力矩缩放、延迟、弹簧曲线，这些不随 Kp/Kd 变化。
- Kp/Kd 是自己选的控制器参数：先用一组临时增益做辨识，把参数写回模型后在仿真里选训练用的增益，再回实车复核一次，然后冻结（见 §7）。

### 1.3 为什么髋电机要在多个姿态做
一条腿的两个髋电机通过五连杆驱动同一个轮心，连杆惯量、被动铰摩擦、重力、弹簧力都经过随姿态变化的雅可比折算到电机上。
- 电机自身的摩擦和转子惯量不随姿态变；
- 被动铰摩擦和连杆惯量折算到电机上的量随姿态变。

只在一个姿态做，这两类参数分不开，换个腿高就不准。所以必须带整条腿、在多个姿态做（华南虎的结论：大部分 gap 来自并联耦合）。

## 3. 髋电机力矩读数标定（手册 §3.8）

8009P 的力矩反馈由电流估算，可能有几个百分点到 10% 的误差，弹簧辨识要用这个读数，所以先标定。

1. 拆掉气弹簧，车架空，机身固定。
2. 在轮轴上挂已知重量（例如 5 kg），绳子保持竖直。
3. 用位置 PD 停在 4 个姿态，每个姿态静止 3 s，取两个电机的平均力矩。
4. 用雅可比算理论力矩 `τ = Jᵀ·[0, −m·g]`，并减去不挂重物时测到的力矩（腿自重）。
5. 每个电机拟合“实测 / 理论”，得到力矩缩放系数。

**完成标准：** 每个电机在 4 个姿态下的比例差异 < 5%。超出时先查几何参数和绳子是否竖直。

## 4. 髋电机扫频（手册 §3.9）

### 4.1 准备
- 车架空，机身固定，轮子离地，不装弹簧。
- 辨识固件用 §1.1 的 PD，在 H7 上 500 Hz 计算。每次运行把所用的 Kp/Kd 写进日志。
- 辨识模式单独设力矩上限，低于正常限幅；幅度从小到大加。通电前按手册 §3.0 检查。

### 4.2 工作点 [判]
腿长取短、中、长 3 档，腿摆角取 2–3 档，共 6–9 个中心姿态。离机械限位和奇异位形留余量。

### 4.3 每个工作点的三种激励 [判]
| 激励 | 做法 | 作用 |
|---|---|---|
| 同腿两电机同相 | 两个电机加同号的偏移 | 和反相一起，分别激励腿长方向和摆腿方向 |
| 同腿两电机反相 | 两个电机加反号的偏移 | 同上；哪种对应腿长取决于正方向定义 |
| 单电机 | 一个电机动，另一个用 PD 保持 | 直接看出两个电机之间的耦合 |

手册写的是“两条腿同相、反相”。机身固定时左右腿在力学上基本独立，信息量更大的是同一条腿两个电机的同相和反相 [判]。左右腿同相、反相成本很低，照手册也做一遍，同时能暴露机架刚度和供电压降的问题。

### 4.4 每种激励的轨迹
| 轨迹 | 参数（起点 [判]） | 主要用来定 |
|---|---|---|
| 慢速三角波往返 | 0.2 / 0.5 / 1 rad/s | 摩擦（同一位置正反方向力矩差的一半）、重力（均值）、粘滞阻尼（随速度的变化） |
| 正弦扫频 | 0.5 → 5 Hz，每段 20–30 s；幅度 ±0.05 rad 起，再到 ±0.1、±0.2 rad | armature、延迟 |
| 阶跃 | 0.1 / 0.2 / 0.3 rad | 超调、力矩饱和 |

用 2–3 组不同增益各跑一遍（例如 Kp 15 / 30 / 60 [判]），范围要覆盖打算在训练里用的值。
- 髋电机从低增益开始，例如 Kp 10–15、Kd 0.5–1（星云的量级），确认不振荡后再往上加。
- 低 Kp 时腿到不了目标位置没关系，拟合用的是实际关节角。
- 几组增益下拟合出的物理参数应当一致；不一致说明模型缺了某个效应。

### 4.5 记录
500 Hz：时间戳、位置指令、4 个关节角和速度、下发力矩、反馈力矩、温度。每次运行另记 Kp/Kd、工作点、激励类型、母线电压 [判]。

### 4.6 拟合顺序 [判]
不要一次搜索全部参数，否则参数之间会互相补偿。
1. **静态：** 各工作点的保持力矩和仿真对比，检查质量、质心、几何。对不上就改模型，不要拿摩擦去凑。
2. **慢速往返：** 定库仑摩擦和粘滞阻尼。
3. **扫频和阶跃：** 定 armature、力矩缩放、延迟。
4. **合并：** 所有工作点、所有增益共用一组参数一起拟合；留一组不参与拟合的数据做验证。
5. **带弹簧验证：** 弹簧辨识完成后，冻结髋电机参数，带弹簧重跑一部分扫频。实车是带弹簧的，最终以这一遍为准。

### 4.7 完成标准（手册 §8.2）
- 扫频 0.5–5 Hz、同相和反相、阶跃，仿真和实车的关节角曲线基本重合；
- 留出组的误差和拟合组相当；
- 高频段的相位差可以用延迟解释。

## 5. 气弹簧（指南 §4 第 5 条，手册 §3.11）

气弹簧不扫频，用准静态网格加匀速往返。

**原理：** 静止时 `τ_电机 = τ_重力(q) + τ_弹簧(q) + τ_摩擦`，其中 `τ_弹簧 = J_s(q)ᵀ·F_s`，`J_s = ∂L/∂q`，L 是由五连杆几何算出的弹簧长度。每个姿态有 2 个电机方程、1 个未知量 F_s，多出来的方程用来检验几何。

1. **无弹簧网格（基线）：** 每条腿在两个电机的工作范围内取约 10×10 个姿态，每个姿态停 1–2 s，取静止后的平均力矩。每个姿态从两个方向各到达一次，用来分离摩擦。
2. **装弹簧，按同样的网格、顺序和 PD 再扫一遍。**
3. **相减：** `Δτ(q) = τ_有弹簧 − τ_无弹簧 = J_s(q)ᵀ·F_s`，重力和电机零偏被消掉。每个姿态用最小二乘解 F_s。
4. **拟合：** `F_s = F0 + k·压缩量`。两个方向的均值是静态力，差的一半是弹簧摩擦（滞回）。
5. **阻尼：** 0.2 / 0.5 / 1 rad/s 匀速往返，减去静态部分后对 `L̇` 拟合，得到 c。
6. **热机复测：** 车运转、电机温度稳定后再测一遍，两次的差值用来检查随机化范围。
7. **左右弹簧分开辨识。**
8. **整车复核：** 落地，在 3 个腿高下静止站立，电机力矩和仿真的差 < 10%。

**完成标准（手册 §8.2）：** 10×10 网格有弹簧、无弹簧各一遍且两个方向；不同速度拟合出阻尼；左右分开；热机前后各一次；两个电机算出的 F_s 一致。两个电机不一致或残差大时，先查弹簧安装点坐标和 L(q)。

**注意 [判]：**
- 拆掉弹簧时弹簧本体的重量也不在基线里，相减后会混进 `Δτ`，量很小，可用 CAD 质量修正。
- 带弹簧停在某些姿态时，保持力矩可能接近 8009P 的额定 20 Nm。缩短停留时间，盯着温度。
- 在弹簧接近自由长度的姿态安装，避免带预压装配。
- 网格要覆盖弹簧的全部行程（75 mm），接近行程两端时放慢。

## 6. 轮电机（手册 §3.10）

轮子不做正弦扫频。

| 测试 | 做法 | 得到 |
|---|---|---|
| 空载速度阶跃 | 轮子离地，10 / 30 / 60 rad/s | 摩擦、阻尼、速度环响应、实测最高转速 |
| 堵转扭矩 | 卡住轮子，C620 给 5 / 10 / 15 / 20 A，拉力计或杠杆加秤测轮端扭矩 | 扭矩–电流曲线、可用最大扭矩 |
| 断电滑行 [判] | 转到高速后电流置零 | 摩擦与惯量之比 |
| 恒电流加速 [判] | 给固定电流，记录角加速度 | 转动惯量，和 CAD 对比 |

- 堵转、恒电流、滑行都是直接给电流，不需要增益。空载速度阶跃用 `τ = Kd_w·(ω_ref − ω)`，`Kd_w` 先取 SCUT 的 0.2。
- 手册的估算值（15.76:1 时空载约 61.5 rad/s、20 A 约 4.9 Nm）只用来和实测对比，不直接填进配置。

**空转够不够：** 空载加堵转就够，不需要专门落地带负载辨识 [判]。
- 落地后轮电机感受到的负载主要是整车质量，来自称重和模型；
- 减速箱带载的效率损失由堵转曲线覆盖；
- 空转测不到轮胎与地面的摩擦和滚动阻力，这部分由随机化（静摩擦 0.5–1.2）覆盖，上车后用实车日志在 MuJoCo 回放验证。

**换轮子之后 [判]：**
| 变化 | 处理 |
|---|---|
| 质量、转动惯量变化在 ±10% 内（随机化范围内） | 更新标称值，重跑评测，不退化就不重训 |
| 轮胎材质变化，摩擦仍在 0.5–1.2 内 | 重跑评测 |
| 轮半径改变 | 必须更新模型（半径没有被随机化）。先跑评测，退化就续训 |
| 半径或轮距变化大到默认姿态、腿高范围要改 | 从头训练 |

流程：重做空载测试 → 更新 `config/robot.yaml`、重新生成资产 → 重跑评测 → 退化才从 checkpoint 续训。电机和减速箱没换时堵转扭矩不用重测。已经确定要换轮子的话，等轮子定型再开始 P1 正式训练。

## 7. 选定并冻结 Kp/Kd [判]

1. 把 §4–§6 的结果写回模型。
2. 在仿真里选训练用的增益。参考值差别很大（SCUT 60/2，星云 15–20/1），要按本车定。看三点：
   - 带上实测延迟后不振荡（Kp 越高对延迟越敏感）；
   - Kd 乘以速度噪声后的力矩抖动可以接受；
   - 动作的力矩分辨率合适：动作每变化 1，目标变 0.5 rad，对应力矩 0.5·Kp。
3. 回实车，用选定的增益带弹簧再跑一次阶跃和扫频，和仿真重合后冻结。
4. 写进各策略的 `policy_meta.yaml`，再开始正式训练。P1、P2、P3 各有一组，切换策略时一起切换。
5. 冻结后再改增益，超出随机化的 ×0.75–1.25 就要续训。

## 8. 结果写到哪里

原始数据和拟合报告留在固件仓库；审核后的参数导入本仓库。字段按逻辑关节顺序 `left_front, left_rear, left_wheel, right_front, right_rear, right_wheel`。

| 辨识结果 | 字段 |
|---|---|
| armature | `robot.yaml: training.joint_armature` |
| 摩擦和粘滞阻尼 | `training.joint_coulomb_friction`、`joint_dynamic_friction`、`joint_viscous_friction` |
| 转速–扭矩包络 | `training.saturation_torque_nm`、`no_load_speed_rad_s`、`wheel_speed_limit_rad_s` |
| 弹簧（左右各一个值） | `training.spring.reference_q_m`、`direction`、`f0_n`、`stiffness_n_m`、`damping_n_s_m`、`hysteresis_n`、`force_limit_n` |
| 延迟 | 随机化范围 `training.randomization.observation_delay_steps`、`action_delay_steps`（每步 2 ms）；评测用 `policy_meta.yaml: training.evaluation.*_delay_steps` |
| Kp、Kd、力矩限幅 | `policy_meta.yaml: kp`、`kd`、`torque_limit_nm`（轮通道的 `kd` 就是 `Kd_w`，`kp` 不参与计算） |
| 完成标记 | `robot.yaml: pending_measurements` 下的 `hip_torque_calibration_and_envelope`、`wheel_torque_calibration_and_envelope`、`motor_sweep_and_held_out_validation`、`spring_left_*`、`spring_right_*`、`measured_sensor_and_action_delay` |

- 弹簧模型见 `wheelleg/tensor_ops.py` 的 `spring_force()`：`压缩量 = clamp(direction·(q − reference_q_m), 0, 行程)`，`F = f0_n + stiffness_n_m·压缩量`，再加阻尼项和 `hysteresis_n·sign(q̇)`。`hysteresis_n` 填两个方向之差的一半。
- 随机化范围按指南 §5.7 的表，不因为进度放宽。实测超出表里范围时，只把那一项扩大到能覆盖实测值。
- 验证：把留出的那组扫频指令放进随机化后的 MuJoCo 跑 50 次，实车曲线应落在这 50 条曲线的范围内。落在外面就回去补辨识，不加宽随机化（手册 §8.3）。

## 9. 待确认

- **三个摩擦字段的含义和单位：** `env_cfg.py` 把它们分别传给执行器的 `friction`、`dynamic_friction`、`viscous_friction`。它们在 Isaac Lab 2.3.2 / PhysX 里是力矩还是系数、和 MuJoCo 的 `frictionloss`、`damping` 怎么对应，要在目标镜像里核对后，再决定拟合脚本输出什么量。
- **力矩缩放系数放在哪里：** 手册写的是固件侧的 `config/hw/torque_scale.yaml`，本仓库没有对应的标称字段，只有随机化范围 `hip_torque_scale`、`wheel_torque_scale`。是在固件里修正读数和指令，还是在模型里加标称缩放，需要定。
- **`pending_measurements` 填什么：** 代码只判断是否为 `null`，没有规定填报告路径、日期还是别的。
- **髋电机的空载转速：** 带着腿、受关节行程限制，很难直接测。是用手册的 17.6 rad/s@24 V，还是用大幅阶跃里的速度饱和段来估，需要定。
- **采集格式：** 遥测协议文档还没有；手册里的文件名是 `hip_sweep_<日期>.csv`、`spring_with_<日期>.csv`、`spring_without_<日期>.csv`。
