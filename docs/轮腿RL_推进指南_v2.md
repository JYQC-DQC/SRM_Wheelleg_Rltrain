## 0. 结论速览

| 问题 | 答案 |
|---|---|
| 训练算法 | PPO（rsl_rl），fork SCUT 的 Isaac Lab 框架 |
| 策略个数 | 3 个：**P1 行走**（平地 + 台阶 + 低姿态起身）、**P2 小陀螺**（含平移）、**P3 跳跃**；外加一个手写的翻倒恢复控制器 |
| 网络规模 | 每个策略约 5 万参数的 MLP：35 → 256 → 128 → 64 → 6，3 个隐藏层，ELU 激活，FP32 约 200 KB。可选加一个约 3 万参数的历史估计器。详见第 7 节 |
| 输入 | 35 维单帧本体观测：指令、腿高指令、角速度、重力投影、4 个髋电机角、6 个关节速度、上一帧动作、7 维模式位 |
| 输出 | 6 维：4 个髋电机的**位置目标**加 2 个轮子的**速度目标**，由 H7 上的 PD 环换算成力矩 |
| 能不能直接输出 6 个电机力矩、不做五连杆解算 | **不用做五连杆解算**：训练时就保留闭链，策略直接对 4 个髋电机下目标（SCUT 就是这样做的）。**不建议直接输出力矩**，理由见 §7.4 |
| 部署 | X-CUBE-AI，FP32 不量化；H7 上推理 100 Hz、PD 500 Hz，单次推理预计 < 1 ms（星云实测 3.9 万参数的模型约 0.6 ms） |
| 训练 GPU | **RTX 4090**；L40/L40S 只在需要 48 GB 显存时才值得租（第 11 节） |

**这套方案能成的依据：** 每个关键环节都至少有一支队伍在实车上做成过，例如闭链加弹簧建模和 H7 部署（SCUT）、多策略切换和跳跃（星云）。新增的部分（跳跃参考轨迹、按回报重置采样、模式位语义）都是在这些已验证组件上的增量，每一项都可以单独关闭回退。

**主要风险：** 跳跃和真正的翻倒自起，开源里没有一个是端到端训练成功的（§6.4、§6.6）。所以这两项都设计成分阶段推进，每个阶段都有不依赖 RL 的保底方案。

## 1. 总体架构

### 1.1 运行时结构（实车）
```
遥控器/操作手 ──► H7 模式状态机 ──► 选择策略 P1 / P2 / P3 / 手写恢复控制器
                         │
IMU、编码器 ──► 观测构造（35 维，100 Hz）──► CubeAI 推理（MLP）──► 6 维动作
                                                               │
                         PD 环（500 Hz）：髋位置 PD、轮速度 D ◄──┘
                                 │
                         安全仲裁 → 功率控制 → CAN → 6 个电机
```

### 1.2 策略划分和理由
| 策略 | 覆盖的功能 | 为什么这样分 | 开源依据 |
|---|---|---|---|
| **P1 行走** | 平地行驶、转向、调高、上下台阶、从低姿态站起、高处落地 | 比赛中平地和台阶连续出现，中途不能切策略；下台阶和落地本质相同 | 星云的"上台阶"策略同时负责起身和下台阶 [码 FD-deploy `chassis.cpp:2137-2149`]；SCUT 的 rough 策略同时包含台阶和平地 |
| **P2 小陀螺** | 原地小陀螺、小陀螺中平移 | 需要较低的 Kp 和高转速样本分布；SCUT 的说明里提到"坐船和平移不可兼得" | SCUT `pretrained/26_infantry/rotation_translation`；星云 Spin 策略 Kp 10 [码 FD-deploy `chassis.cpp:116-167`] |
| **P3 跳跃** | 原地跳、行进跳、落地 | PD 增益、轮扭矩限幅都不同，又有相位，和 P1 的奖励冲突 | 星云 Jump 策略 Kp 6 / Kd 0.5，轮扭矩 ±4 Nm |
| **R 恢复控制器（手写）** | 侧翻、倒扣后推回低姿态 | 开源中没有 RL 端到端自起成功的例子 | 星云 LargeRecover：腿长 PD + 腿角 PI [码 FD-deploy `chassis.cpp:1306-1383`] |

### 1.3 推进路线（每一步通过了才进下一步）
| 阶段 | 内容 | 产出 |
|---|---|---|
| A | 环境搭建 + 5 分钟冒烟测试（不复现 SCUT） | 环境可用 |
| B | 你的机器人建模（USD 闭链 + 弹簧关节 → MJCF） | 模型验收通过 |
| C | 辨识（real2sim 回放、延迟、弹簧曲线） | 参数写回模型 |
| D | **P1-平地** PPO → sim2sim → H7 → 实车 | 第一个实车里程碑 |
| E | P1 加"高处落地" | 抗跌落、抗下坎 |
| F | P1 加台阶 | 上下一级/二级台阶 |
| G | P1 加低姿态起身，接上 R 控制器 | 翻倒后能自己恢复 |
| H | **P2 小陀螺**（从 P1-平地续训） | 小陀螺加平移 |
| I | **P3 跳跃**（从 E 阶段的 checkpoint 续训） | 原地跳和行进跳 |
| J | 策略切换和整车联调 | 比赛动作序列 |

H 可以提前到 D 之后做，取决于比赛对小陀螺的需求有多急。F 和 G 都是在改 P1，必须先后进行；H（P2）和 I（P3）是各自独立的策略，可以和 F、G 同时开训。

## 3. 阶段 B：建模（约 2–3 周，最关键的一步）

### 3.1 目标结构：完全照 SCUT V14_2 的做法
- **闭链：** 在 USD 里用 loop 关节闭合（树结构之外的关节）。策略直接驱动 4 个髋电机关节（`*_front1_joint`、`*_rear1_joint`）；其他连杆关节（`front2/3/4`、`rear2`）为被动关节，kp = 0，kd = 0.01 [码 SCUT `wheelbipe_V14_2.py:62-153`]。
- **气弹簧：** 闭链中的一个**棱柱关节** `*_spring2_joint`，每个控制步用 `set_joint_effort_target` 写入弹簧力。SCUT 的线性模型是 `F = 400 + 200/0.07·max(0.06076 − q, 0) ± 50` N [码 SCUT `env.py:5554-5574`]，你要换成自己 450 N 弹簧的曲线；**你的弹簧行程是 75 mm**（SCUT 模型里是 70 mm），棱柱关节的行程限位按 75 mm 设置。弹簧阻尼由执行器 kd = 50 提供。
- **求解器：** 位置迭代 12、速度迭代 6；物理 500 Hz（§5.1）；关闭自碰撞 [码 SCUT `wheelbipe_V14_2.py:42-43`]。如果剧烈落地时闭链仍然脱开，再增加求解迭代次数。
- **关节命名：** 和 SCUT 一致（`l_/r_` 加 `front1..4`、`rear1/2`、`spring1/2`、`wheel`、`guide`）。这样 SCUT 的配置和 SMW 的工具（`spec.py` 按名字匹配关节）都能直接用。

### 3.2 SolidWorks → USD
1. SolidWorks 装配体整理：
   - 只保留会动的刚体，螺钉、线束的质量并入所属刚体；
   - 整车质量和实测的差应在 2–3 kg 以内（星云经验），越小越好；
   - 统一坐标系：x 朝前、z 朝上，腿在 xz 平面内运动；
   - 量出五连杆杆长、弹簧安装点、零位姿态下的各关节角。
2. 用 SolidWorks to URDF 插件导出**树结构**：每条腿在一个不带轮子的铰点处切开闭环，气弹簧导出为一个棱柱关节加两端的转动关节。
3. 用 Isaac Lab 的 URDF 转换器转成 USD [核]，再用脚本补上 loop 关节（`excludeFromArticulation = true` [核]）。也可以照华南虎文章里的"从 solidwork 导出 anything V1/V2"文档做。**USD 只能用脚本生成，不要手改**，模型每次修改都重跑脚本。
4. 碰撞体全部换成简单几何体，轮子用圆柱，半径用实测值。
5. **云台：** 把云台（yaw、pitch、发射机构）合成**一个刚体**，用一个 yaw 转动关节连到机身；pitch 不单独建关节。云台的质量和惯量从 SolidWorks 导出。
   - 训练时云台 yaw 由一个 PD 控制器保持世界系朝向（SCUT 的 heading PD，kp 20–40、kd 0.05–0.1 随机化 [码 `V14/env_cfg.py`]），这样小陀螺时云台不跟着底盘转，和实车一致；
   - 实车用 GM6020，PD 增益的随机化范围要覆盖 6020 实际的跟随特性；
   - 云台的惯量会影响小陀螺时底盘的反作用力矩，所以一定要单独作为刚体建模，不能并进机身。

### 3.3 USD → MJCF（sim2sim 用）
用 SMW 的 `tools/usd2mjcf.py` 从同一份 USD 生成 MJCF：闭链转成 `equality connect`，弹簧转成 motor 执行器 [码 SMW `usd2mjcf.py:267, 410-414`]。这一步不需要启动 Isaac，只用 pxr。生成后在 XML 里**显式写上 `timestep`**（星云就漏了这一项，见 §10 第 6 条）。

### 3.4 模型验收（直接用 SMW 的工具，改一下关节名即可）
| 检查 | 工具 | 通过标准 |
|---|---|---|
| 运动学 | `tools/calibrate.py` 的 FK 校验 | 误差 ≤ 1 cm [码 SMW README] |
| 零动作静置 | `calibrate.py` 的 settle（120 步） | 倾角 cos ≥ 0.9；机身不会持续下沉。下沉通常说明弹簧方向或大小错了 |
| 弹簧力 | `calibrate.py` | q = 0 时的弹簧力与手算一致 |
| 双引擎一致 | `tools/verify_against_isaac.py` | 用 Isaac 录下的轨迹回放 MuJoCo，曲线吻合 |
| 动态脱链 | 自己写：1 m 自由落体、全力矩阶跃 | 闭链不脱开，不翻到另一个装配解 |

## 4. 阶段 C：辨识（与 B 并行，约 1–2 周）
1. **称重：** 整车、单腿、轮子分别称；测出质心高度。
2. **髋电机 real2sim 回放**（SCUT 推荐）：
   - 把车架空，髋电机按正弦扫频（0.5–5 Hz）、阶跃、两腿同相和反相的轨迹运动，H7 记录指令、角度、速度、电流；
   - 在 MuJoCo 里输入同一组指令，调整 armature、关节摩擦、阻尼、Kp 缩放和力矩上限，直到两边曲线重合；
   - 必须带着整条腿做，不能只辨识单个关节。SCUT 发现大部分 gap 来自并联耦合。
3. **轮电机：** 静摩擦、粘滞阻尼，以及可用的最大轮端扭矩。星云用 3508 + 16.33 减速，约 5 Nm；你改用 15.76:1 后，按手册估算约 4.9 Nm（§13），以实测为准。
4. **延迟：** 回放对比时，仿真曲线和实车曲线的时间差就是总延迟；再在 H7 上逐段打时间戳分开测量。SCUT 训练用的范围是观测 5–15 ms、动作 5–10 ms [码 SCUT `V14/env_cfg.py:504-528`]，作为初始值；按 2 ms 物理步换算，见 §5.7。
5. **气弹簧（装在车上，只用电机力矩来辨识）** [判]：
   - **原理：** 腿在某个姿态 q 静止时，电机力矩满足 `τ_电机 = τ_重力(q) + τ_弹簧(q) + τ_摩擦`，其中 `τ_弹簧 = J_s(q)ᵀ·F_s(L(q))`。L(q) 是由五连杆几何算出的弹簧长度，`J_s = ∂L/∂q`。每个姿态有 2 个电机，也就有 2 个方程，但未知量只有一个 F_s，方程比未知量多，可以顺便检验几何模型对不对。
   - **步骤：**
     1. **标定力矩读数：** 先拆掉弹簧，在轮轴上挂一个已知重量（例如 5 kg 哑铃），放在 3–4 个姿态下，把电机读到的力矩和用几何算出的力矩相比，得到每个电机的力矩缩放系数。8009P 的力矩是由电流估算的，可能有几个百分点到 10% 的误差。
     2. **不带弹簧扫一遍：** 车架空，机身固定，轮子离地。每条腿用位置 PD 在两个电机的工作范围内走一个网格（约 10×10 个姿态），每个姿态停 1–2 s，取静止后的平均力矩。每个姿态往两个方向各到达一次（从左边过来、从右边过来），用来分离摩擦。这一遍测出的是重力加摩擦，`τ_无弹簧(q)`。
     3. **装上弹簧，按同样的网格和顺序再扫一遍**，得到 `τ_有弹簧(q)`。
     4. **相减：** `Δτ(q) = τ_有弹簧 − τ_无弹簧 = J_s(q)ᵀ·F_s`。重力和电机零偏都被消掉了。对每个姿态用最小二乘解出 F_s，再画成 F_s 对 L 的散点图。
     5. **拟合：** `F_s(L) = F0 + k·(L0 − L)`。两个方向的均值是静态力，两个方向之差的一半是弹簧摩擦（滞回）。如果拟合残差大，或者两个电机算出的 F_s 不一致，先检查安装点坐标和 L(q) 的几何。
     6. **阻尼：** 用不同速度（例如 0.2 / 0.5 / 1 rad/s）匀速往返扫一遍，减去静态部分后，剩下的和 `L̇` 拟合，得到阻尼系数 c。这一步也可以放进 real2sim 回放（第 2 条），把 F0、k、c 作为待辨识参数，和 armature、关节摩擦一起拟合。
     7. **复核：** 整车放在地上，在 3 个腿高下静止站立，读出电机力矩，与仿真里同样姿态的静态力矩对比。
   - **注意事项：**
     - 气弹簧的力随温度上升而变大，要在车已经运转、电机温度稳定后再测一遍，两次的差值计入随机化范围；
     - 网格要覆盖弹簧的全部行程，接近行程两端时速度要慢；
     - 两条腿的弹簧分别辨识，用于"左右分别随机"（§5.7）。
   - **可选的便宜做法：** 用一台电子秤加台钳（或杠杆），在 3–4 个压缩量下读力，作为上面结果的交叉验证。
6. **剧烈工况：** 做堵转力矩阶跃，看力矩响应的滞后、超调和抖动（SCUT 发现跳跃时这部分 gap 很明显），把测到的滞后时间计入动作延迟的随机化上限。

## 5. RL 共享设计（三个策略共用）

### 5.1 节拍
| 项 | 值 | 来源 |
|---|---|---|
| 物理步长 | **2 ms（500 Hz）**，`sim.dt = 0.002` | 你的决定；SCUT 文章说 500 Hz 对闭链精度的改善比加迭代次数更明显 |
| 策略周期 | **10 ms（100 Hz）**，`decimation = 5` | 和星云的 100 Hz 一致 |
| PD 计算 | 每个物理步算一次（IdealPD / DCMotor），即 500 Hz | H7 上 PD 也按 500 Hz 运行，和训练一致 |

**改用 500/100 Hz 的影响和需要同步修改的地方** [判]：
1. **训练变慢。** 每秒仿真时间的物理步数是 200 Hz 时的 2.5 倍，同样仿真时长的墙钟时间大约变成 2–2.5 倍。4090 仍然够用，只是每次实验要多等一些时间。
2. **PPO 的时间尺度要跟着改：**
   - 折扣 γ 从 0.99 改为 **0.995**，让有效视野仍约 2 s（1/(1−γ) 步 × 10 ms）；
   - 每个环境的采样步数从 24 改为 **48**，让每段 rollout 仍约 0.48 s。
3. **延迟改用 2 ms 一步来计：** 观测延迟 3–8 步（6–16 ms），动作延迟 3–5 步（6–10 ms），实测后再调整。
4. **SCUT 和 SMW 的预训练权重、超参数都是 50 Hz 下的，不能直接用。** 不过奖励项都乘了 dt，权重可以照抄，只有 `action_rate`（相邻两帧的动作差）需要观察：100 Hz 下相邻帧的差会变小，这一项的惩罚效果会变弱，必要时把权重加倍。
5. **跳跃：** 蹬伸约 0.15 s，在 100 Hz 下有 15 个控制步，比 50 Hz 时的控制更细。
6. **H7：** 控制周期 2 ms。每条腿一路 CAN：2 个 8009P（500 Hz 控制帧加反馈帧，约 2000 帧/s），加 1 个 C620（控制帧 500 帧/s，反馈默认 1 kHz），合计约 3500 帧/s，每路负载约 45% [判]，还在可接受范围内，但不要再往这两路总线上加设备（§9.4）。推理 100 Hz × 约 1 ms，CPU 占用约 10%。

### 5.4 动作和执行器
- **动作裁剪（与华南虎一致，v2.1 核对代码后更正）：** 华南虎**不裁剪网络原始输出**（rsl_rl 的 `clip_actions: null` [码 SCUT `pretrained/.../params/agent.yaml:7`]），只裁剪换算后的目标：腿的位置目标 `q_ref` 限制在 `[lower_joint_limit, upper_joint_limit] = [−3.14, 3.14]` rad [码 SCUT `wheelbipe25_v3/env_cfg.py:400-401`，`env.py:2871-2875`]；轮的速度目标限制在 ±max_wheel_vel [码 `env.py:2887-2891`]。我们照这个做：`action_clip = null`（原始输出不裁剪），腿目标按关节限位裁剪，轮目标裁剪到 ±65 rad/s。华南虎的 ±3.14 rad 只是一个占位值，实际上几乎不起作用；**建议把腿目标的裁剪范围换成实测的机械限位（再往里收 0.05 rad）**，这和华南虎的写法一致，只是数值更真实 [判]。固件的安全仲裁仍然另外负责关节越限和力矩限幅。
- **髋（DM-J8009P-2EC，参数见 §13）：** `q_ref = clip(q_default + 0.5·a, q_min, q_max)`；`τ = Kp·(q_ref − q) − Kd·q̇`。
  - 峰值扭矩 40 Nm，额定扭矩 20 Nm；armature 用 SCUT 的 1.95e-4 × 81（9:1 减速）[码 SCUT `wheelbipe_V14_2.py`]。
  - **必须加转速–扭矩包络。** 手册给的空载最大转速是 168 rpm@24V = 17.6 rad/s。SCUT 的 IdealPD 设了 `velocity_limit = 17`，但这个参数对 IdealPD 不起作用 [码 SCUT 报告]。改用 Isaac Lab 的 `DCMotorCfg` [核]：`saturation_effort = 40`，`velocity_limit = 17.6`，`effort_limit = 40`，扭矩上限随转速线性下降。跳跃蹬伸时关节转速会接近这个极限，不加包络，仿真里的起跳就会比实车强。
  - 母线电压会随电池电量和瞬时负载下降，空载转速大致与电压成正比，所以把 `velocity_limit` 随机化 ×0.85–1.0 [判]。
- **轮（M3508 换 15.76:1 减速箱，参数见 §13）：** `ω_ref = 10·a`；`τ = Kd_w·(ω_ref − ω)`。
  - 扭矩上限：**±4.4 Nm**（C620 最大电流 20 A 对应约 4.9 Nm，留 10% 余量）；P3 跳跃 ±4.0 Nm（星云跳跃时也是比平时低约 1 Nm）。
  - 轮速裁剪到 ±65 rad/s（空载约 61.5 rad/s）。SCUT 的 ±150 rad/s 对你的电机没有意义。
  - 加转速–扭矩包络：空载约 61.5 rad/s。
  - `Kd_w` 先取 SCUT 的 0.2，再按辨识结果调整。

  4.9 Nm 和 61.5 rad/s 都是按手册估算的，你的减速箱效率未知，要实测 [判]。
- **各策略的 PD 是策略参数的一部分：** P1 先用你辨识得到的值（SCUT 是 60/2，星云是 15–20/1，差别很大，按 real2sim 定）；P2 的 Kp 比 P1 低约 1/3（星云用 10 对 15）；P3 用低 Kp（星云 6/0.5）。低 Kp 下位置目标近似成为力矩指令（BeyondMimic/SuperMimic 附录 A 的说法），这正是跳跃需要的。
- 轮子执行器的一个坑：SMW 注释写着"轮速伺服必须用 ImplicitActuatorCfg，IdealPD 保持 20 ms 力矩会让低惯量轮子振荡到 ±50 rad/s"[码 SMW `robot.py:148`]。SCUT 用的是 IdealPD（每个物理步更新一次），只要不在 20 ms 里保持同一个力矩就没事。你上车前在 sim2sim 里看一下轮速曲线。

### 5.6 指令：用"指令片段库"代替逐次独立重采样（借鉴 SuperMimic 的动作库）
SuperMimic 用"一个动作库加按难度重置"来覆盖整个任务空间。轮腿没有动作数据，SMW 把动作库换成了速度指令片段库（`CommandLib`，每段 5–15 s）[码 SMW `command.py`]。我们这样做 [判]：
1. 每个环境拿到的是一段**指令时间线**，由若干段常值拼成，每段 3–15 s。段与段之间用**斜率限制**过渡：vx 不超过 2 m/s²，ωz 不超过 10 rad/s²（SMW 的手柄设置 [码 `play_mujoco.py`]）。
2. 段的类型按比例抽取：

   | 类型 | 比例 | 内容 |
   |---|---|---|
   | 站立 | 10% | 指令全为 0 |
   | 直行 | 25% | — |
   | 转向 | 15% | — |
   | 直行 + 转向 | 25% | — |
   | 冲刺 | 10% | vx 2–3 m/s（SCUT 的 dash 模式） |
   | 急停 / 倒车 | 15% | — |

3. **H7 上的指令斜率限制要和训练完全一样。** 操作手推杆不可能比训练分布更快，部署时也不会出现训练中没见过的指令突变。
4. 腿高指令单独成一条时间线，段长 2–6 s，范围按你的机构设置（SCUT 是 0.20–0.42 m [码 `V14/env_cfg.py:564`]）。 **v2.2：** 华南虎参考配置用 0.20–0.35 m。

### 5.8 奖励设计原则（综合 SuperMimic、BeyondMimic 和两队经验）
1. **任务项一律用核函数 `exp(−e²/σ)`，并配一个平方惩罚项**，SCUT 的做法是 `track_x`（+1）配 `track_x_square`（−1）[码 `V14/env_cfg.py:869-914`]。核函数在误差小时梯度大，平方项在误差大时梯度大，两者互补。σ 先取宽，学会之后再收紧（SCUT 跳跃收腿用的"先松后紧"）。
2. **稀疏目标改成跟踪参考轨迹**（SuperMimic 的核心经验：跟踪任务每一步都有稠密奖励，所以训练很稳定）。跳跃、起身、上台阶时的收腿，都先构造一条参考曲线再去跟踪（§6.4、§6.6）。
3. **不要用辅助力退火**来教跳跃。SCUT 的分析是：辅助力衰减时，动作需要变大，PPO 却会把"增大动作"判断为错误的方向。
4. **每项奖励都乘 dt，再做单项裁剪**（星云的 `clip_single_reward`，jump 中为 2.5 [码 FD-train `legged_robot.py:322-331`]），防止某一项在异常状态下主导梯度。
5. **终止惩罚：** SCUT 用 −200；SMW 发现，配合按回报重置采样时 −200 会让采样权重放大约 40 倍，所以改成 −20 [码 SMW `docs/upstream.md`]。我们用 §5.9 的采样，所以先取 −50，并对 `G/G_max` 做截断 [判]。
6. **每项奖励都单独记日志**（SCUT 有 CSV/HTML 导出），按项诊断，不要只看总回报。

### 5.9 按回报重置采样（SuperMimic 附录 D.1，移植到 PPO）[判]
SuperMimic 把动作时间轴切成 1 s 的 bin，偏向回报低的 bin 重置，用来防止困难样本被平均掉。我们把 bin 定义为"任务 × 难度"：

| 策略 / 阶段 | bin 的划分 |
|---|---|
| P1 平地 | 指令区间网格：vx 6 档 × ωz 5 档 |
| P1 台阶 | 台阶高度 8 档 × 上 / 下 |
| P1 起身 | 起始姿态类型：侧倒、前扑、后仰、低蹲，再乘以腿部构型 |
| P2 | 转速 4 档 × 平移速度 3 档 |
| P3 | 目标跳高 5 档 × 原地 / 行进 |

- 每个 bin 维护一个折扣回报的滑动估计 `G_b`，在策略自己的 rollout 上更新。
- 每次重置时：50% 均匀抽 bin，40% 按 `softmax(−25·G_b/G_max)` 抽（G_max 是可达到的最大折扣回报），10% 按历史 softmax 权重抽（已经学会的内容不至于被遗忘）。
- 和 Isaac Lab 的 terrain_levels 地形课程同时使用：地形课程管"去哪块地形"，这里的采样管"给什么指令或目标"。
- 先实现"均匀采样"版本作为对照，确认按回报采样确实能更快达到同一个评测成功率，再保留它。

### 5.10 终止条件
- roll 或 pitch 超过 40°，或者机身（含云台）、导轮、腿连杆接触地面（超过 3 N）。SCUT 的名单是机身、云台和导轮 [码 SCUT `V14/env.py:134-145`]；腿连杆是 v2.2 加的；
- **v2.2：** 上述条件累计满 0.4 s 才终止；条件中断时计数按 2 s 回落到 0，而不是像 SCUT 那样清零，否则“碰一下抬一下”的间歇撑地永远不终止。出生后 1 s 内不按倾倒/触地终止。数值异常立即终止；
- **起身相关的 episode 不使用倾角终止**，只用超时（§6.4）；
- 跳跃 episode 在空中阶段放宽倾角阈值（SCUT 在 airborne 期间 termination ×6 [码 `V14/env_cfg.py`]，意思是空中摔倒罚得更重，但不立刻终止）。

### 5.12 评测体系（借鉴 SuperMimic 按动作组统计失败数）

## 6. 各策略的训练（按阶段 D → J 的顺序）

### 6.1 阶段 D：P1-平地（第一个要训练的策略）
- **起点：** SCUT 的 `Flat-v0` 配置，把资产换成你的机器人。
- **奖励：** 照搬 SCUT V14 Flat-v0 [码 `V14/env_cfg.py:869-914`]：

| track_lin_vel_xy | +1 | exp(−e²/0.5)，e 是机体前向速度误差，按 cos(pitch) 投影 |

| lin_vel_z / ang_vel_xy | −0.5 / −0.05 | — |
| no_fork / no_fork_square | −1 / −1 | **防劈叉**：两个轮心在机体 x 方向（前后）的错开量超过 0.05 m 就惩罚，第一项是二值的，第二项是 `(5·max(\|dx\|−0.05, 0))²`。来自华南虎 V14 [码 `V14/env_cfg.py:869-914`；SMW `mdp.py:273-281` 有同样的实现]。轮心位置由五连杆正解得到 |

| undesired_contact | −2 | 机身、大腿接触力超过 3 N |
| stand_still_lin_vel | −1 | 零指令时的速度，死区 0.1 |
| joint_torque / wheel_power | −1e-4 / −1e-4 | — |
| action_rate | −0.01 | — |
| termination | −50（§5.8） | — |

- **指令：** 用 §5.6 的片段库，vx 和 ωz 的范围按课程逐步放大，最终 vx ±2.7 m/s、ωz ±2π rad/s（SCUT 的范围）。
- **通过标准：** 评测集 0 次摔倒；速度误差小于 0.1 m/s；零指令下 10 s 漂移 < 0.2 m [判]。
- **之后：** 第 8 节 sim2sim → 第 9 节部署到 H7 → 实车平地测试。**这是第一个硬里程碑，实车平地没过，不要进入后面的阶段。**
- **v2.2 修订（实现以 `config/reference/scut_p1.yaml` 为准）：** 上表“照搬 SCUT”在本项目的设置下学成了腿折叠、靠导轮和连杆撑地不动，原因见 [经验教训](LESSONS.md)。改动如下，都还没有收敛证据：
  - 出生：训练回合随机腿长 0.13–0.32 m、摆角 ±0.6 rad、机身 roll/pitch ±0.15 rad、朝向随机；出生后 1 s 不按倾倒/触地终止。SCUT 的摆角是 −90°–135° 且约一半回合倒地出生，这里没有采用，倒地出生放在 §6.4。
  - 高度：指令 0.20–0.35 m；新增宽核 `track_height_wide`（σ 0.025，+2，第 2000 轮起在 500 轮内退到 +0.5）；高度平方项保持 −1。
  - 高度门控：高度误差 5 cm 内速度/转速的跟踪奖励和误差惩罚全额，10 cm 外为 0（SCUT 的 linear_band，它默认关闭）。
  - 指令和课程：死区 0.1 内的指令按 0 跟踪；课程从 40% 起步，升级门槛 = 0.1 + 0.25×回合平均指令幅值，且回合平均高度误差小于 5 cm；课程进度写入 `Curriculum/command_fraction`，各条件的通过率写入 `Curriculum/pass_*`。参考配置的转向上限取 ±5 rad/s，“直行加转向”片段的转向等比例缩到 ±3 rad/s 以内；轮速目标上限取 100 rad/s（SCUT 的配置值，它的代码再乘 1.5 得 150；原先取 60，轮子只有速度阻尼，目标封顶后高速下没有力矩留给平衡，第四轮训练的课程因此停在 0.85）。
  - 权重：`lin_vel_error` −8、`undesired_contact` −4（二值，名单见 §5.10）、`stand_still` 改为速度绝对值；新增 `leg_joint_vel` −0.005、`wheel_vel` −1e-5、`action_smoothness_leg` −0.05、`action_smoothness_wheel` −0.01；`termination` 实现为每次 −4（等于 SCUT 的 −200×0.02 s），不是上表的 −50。
  - 腿位置目标限幅 ±3.14 rad（SCUT 的值）；`value_loss_coef` 4.0（V14 实际继承的值）。

### 6.2 阶段 E：P1 加高处落地（照 SCUT Flat-v1 [码 `V14/env_cfg.py:1462-1670`]）
- 30% 的环境从空中出生：高度 0.12–0.42 m，vx ±2.5 m/s。v2.2 按 SCUT 补全：roll ±0.1、pitch ±0.2 rad，vy ±0.5 m/s，角速度上限 0.05、0.1、0.5 rad/s，腿长 0.15–0.35 m，腿摆角 ±45° [码 `V14/env_cfg.py:1488-1521`]。
- 启用 airborne 状态机：
  - 进入条件：机身高于 0.3 m，两个轮心都高于 0.14 m，且持续 0.02 s；
  - 退出条件：轮子受力超过 20 N 且轮心低于 0.15 m 持续 0.3 s，或最长 1 s [码 `airborne.py:712-831`]。
- 空中阶段新增奖励：关节限位 −10、轮子回中 +10、空中轮扭矩归零 +20（σ 1.5）、触地前轮速与行进方向对齐 ±10。airborne 期间 undesired_contact ×25、termination ×6。
- **v2.2 补充：** 腾空期间关闭俯仰惩罚和高度平方惩罚，高度门控置 1 [码 `V14/env_cfg.py:1549-1562`]；空中出生后 3 s 内指令限幅 vx ±2.5 m/s、ωz ±0.5π rad/s [码 `V14/env_cfg.py:1510-1516`]；落地及之后的阶段把 action_rate、两个动作二阶差分、leg_joint_vel、wheel_vel 降到平地权重的 1/5。SCUT 在 50 Hz 下把二阶差分降到 1/10，这里按本项目的权重统一 ×0.2，不照抄数值。
- 随机腿姿出生和高度门控（§6.1）在落地、台阶、起身阶段同样生效。
- 作用：抗跌落、抗下坎，并且是 P3 跳跃的起点（P3 从这个 checkpoint 续训）。

### 6.3 阶段 F：P1 加台阶
- **目标：** 和星云一样，能上下比赛场地里的普通台阶（单级台阶、连续两级台阶）。**不做**制高点的三级台阶。
  - 星云的台阶训练用 trimesh 地形，只有上台阶和下台阶两种，台阶高 `0.05 + 0.18·difficulty`（5–23 cm），台阶宽 0.7 m [码 FD-train `terrain.py:129,162-166`]。他们的 MuJoCo 测试场景里有 20 cm 和 35 cm 的台阶 [码 FD 报告]。
  - 你按比赛场地实际的台阶高度定训练上限：上限取场地台阶高度 × 1.2，下限 2 cm。 **v2.2：** 中央高地外侧平台高 200 mm、宽 800 mm，路面高 300 mm（RMUC 2027 规则手册 V1.0.0 图 4-27，从图上读数，图中 350、360 mm 两个标注的含义未确认）；训练取台阶高 0.02–0.24 m、踏面 0.8 m。
- **地形：**
  - 课程起点用 Flamingo 的台阶配置（90% 倒金字塔，台阶高 2–13 cm，宽 0.4 m [码 FLM `stair_config.py`]）；
  - 往上用星云的上下台阶比例（各 50%），宽 0.7 m；
  - 混入 20% 的 SCUT 平地和低坡（`RM_ROTATION_TERRAINS_CFG_99`）。
  - v2.2：另加 10% 随机起伏地面（噪声 0–3 cm，SCUT `RANDOM_UNIFORM_FOR_RM`）；SCUT 定义了波浪地形但没有启用，这里也不加。当前占比：平地 30%、单/双台阶各 20%、坡 10%、凸起 10%、起伏 10%。
  - SCUT 的 `RM_ROUGH_TERRAINS_CFG` 带 0.40 m 的高台阶和断崖，超出这个目标，不需要。
  - **SCUT 只按行设置难度，没有地形等级晋升**，要加上 Isaac Lab 的 terrain_levels 课程：走出地块一半距离就升级，走不到 1/4 就降级。
- **场地里的坡道和起伏路段**（比赛规则手册 §4.3、§4.4）：梯形高地高 200 mm，有 23° 坡；中央高地两端有 12°、14° 坡；公路区有 11°、15° 坡和起伏路段（按一定间距排布的凸起）。P1 的地形里要加上 0–25° 的坡和凸起路面，凸起的尺寸按场地图纸设置 [核]。 **v2.2：** 凸起高 70 mm、间距 240 mm（RMUC 2027 规则手册 V1.0.0 图 4-37）；训练用高 0.01–0.07 m、宽 0.12 m 的矩形条近似三角形截面。
- **2027 规则的变化**（前瞻手册，以正式版为准）：飞坡改成了隧道，可以跨越，也可以从里面穿越。如果要穿越隧道，等正式版公布尺寸后，按隧道的净空高度设定 P1 的腿高指令下限，并在训练里加入"低姿态长时间行驶"的指令段。原来为飞坡准备的策略不再需要。
- **台阶信号（stair 位）：** 训练时，前方 0.5 m 内出现高差 ≥ 5 cm 就置 1；另有 10% 的概率误报、10% 的概率漏报，用来增强鲁棒性 [判]。实车上由操作手按键（或者前向 TOF）给出。
- **高度指令抬升：** 照 SCUT 的 step_up，前方 0.12–0.14 m 处有台阶时，腿高指令 +0.16 m，保持 2 s [码 `V14/env_cfg.py:721-736`]。实车上由按键触发，执行同样的抬升逻辑。
- **新增奖励：** 前进进度（沿指令方向的位移）+1；卡住（有指令但 1 s 内位移 < 5 cm）−1；机身、大腿碰台阶由 undesired_contact 处理；下台阶落地冲击（髋力矩峰值）−1e-3 [判]。
- **防遗忘：** 至少 30% 的环境保持平地，并使用 6.1 的指令分布。
- **通过标准：** 场地普通台阶（单级、连续两级）上下的成功率 ≥ 95%（阈值你来定）；平地评测不退化。

### 6.4 阶段 G：低姿态起身 + 手写恢复控制器 R
开源里没有人用 RL 训练出完整的自起，所以分成两段做 [判]：
1. **R（手写，H7 上运行）：** 照星云 LargeRecover 写，用腿长 PD（目标 0.342 m，Kp 2000，Kd 60，±100 N）加腿角速度 PI（12/12，±80），把机器人从侧倒、前扑推到低姿态 [码 FD-deploy `chassis.cpp:1306-1383`]。参数按你的机器人重新整定。
2. **先在仿真里跑一遍 R：** 用 Python 写一份同样的 R，在 Isaac 里从随机翻倒姿态开始运行，**记录它结束时的状态，组成一个"接管状态库"**。这借用了 SuperMimic/Dyna 从回放状态出发的思路。 **v2.2：这一步取消，不采集接管状态库。**
3. **P1 学会从低姿态站起来：**
   - 10–15% 的环境从 SCUT 的“地面复位”状态开始（v2.2：不再使用接管状态库）：机身水平地从 0.25 m 落下，腿接近水平（腿长 0.14–0.36 m，轮心在髋轴下方 −0.06–0.12 m，约 40% 腿朝前），前 0.2 s 零力矩，前 1.5 s 指令置零 [码 `cfg_utils.py:198-226`]；
   - 这部分环境的 recover 位（31）在前 1.5 s 置 1；
   - 奖励：一条参考曲线，让机身高度在 1.5 s 内从当前值平滑升到指令高度，用核函数跟踪；姿态核函数；冲击和关节速度惩罚；
   - 这部分环境不用倾角终止，超时设为 5 s。
4. **R 到 P1 的切换条件：** |roll| < 20°、|pitch| < 30°，且角速度较小。这个阈值和接管状态库的范围保持一致。 **v2.2：** 没有状态库后，训练里的倒地出生是机身水平落下，R 交接时的倾斜姿态没有覆盖，需要时给倒地出生加倾角随机。
5. **可选：** 先在仿真里确认机构能完成全程自起，再尝试用 RL 端到端训练，但不列为必须完成的项。

| 项 | 权重 |
|---|---|
| gimbal_spin_track_lin_vel_yaw_frame | +1（σ 0.25） |
| lin_speed | +1 |
| heading | +5（σ 0.025） |

### 6.6 阶段 I：P3 跳跃（从阶段 E 的 checkpoint 续训，综合三家的做法）
**触发与相位**（照 Flamingo 的 EventCommand [码 FLM `mdp/event_command.py:79-104`]）：
- 每个 episode 先正常行驶至少 2 s，然后在随机时刻触发跳跃。约 70% 的 episode 有 1 次跳跃，10% 有 2 次，20% 不跳。不跳的 episode 用来学会"没收到指令就不跳"。
- 触发后，jump 位（32）置 1，相位 φ（34）在事件时长 T_ev 内从 0 线性增到 1，T_ev 约 1.2 s；目标跳高 h\*（33）在事件开始时采样。
- 跳跃过程中 vx 保持触发时的值，用于行进跳；原地跳时 vx = 0。星云实车在跳跃时用"起跳时的 vx − 0.1"[码 FD-deploy `chassis.cpp:1899-1988`]。

**先回答一个问题：给参考曲线加稠密跟踪奖励，策略会不会就照着曲线动？** 会。被跟踪的量会被策略尽量贴住。所以有两条规则 [判]：
1. **只跟踪少数几个关键量，并且跟踪得宽松。** 关键量指下蹲深度、蹬伸末速度、腾空收腿、落地前伸腿。整条关节轨迹和机身高度曲线都不跟踪。各关节怎么配合、什么时候发力，留给策略自己去优化。
2. **参考必须是物理可行的，并且按目标跳高单独算出来。** 不可行的参考会让策略两头都做不好：既跟不住曲线，也跳不起来。下面先做可行性计算，再定参考。

**第一步：可行性计算**（训练前做一次；换机构、电机或弹簧后要重做）
1. 用你的五连杆几何算出腿长范围 `[l_min, l_max]` 和雅可比 `J(q)`。雅可比把两个电机的转速换算成腿的伸长速度 `l̇`，也把电机扭矩换算成腿上的力 `F = J^{-T}·τ`。
2. **转速上限：** 8009P 空载 17.6 rad/s，扭矩随转速线性下降（§13.1）。算出接近 `l_max` 时腿能达到的最大伸长速度 `l̇_max`。这近似就是离地速度的上限，对应 `h_speed ≈ l̇_max²/(2g)`。
3. **能量上限：** 在蹬伸行程 `d = l_max − l_min` 上，`∫(F_电机(l) + F_弹簧(l) − m·g) dl ≥ ½·m·v_rel²`，m 取机身质量（含云台、电池）。由此得到 `h_energy`。
4. **可行跳高：** `h_feasible = 0.8 × min(h_speed, h_energy)`。目标跳高的上限不超过这个值。
5. **更省事的办法：** 在 Isaac 里写一个手动的"满力矩蹬伸"脚本：先下蹲到 l_min，然后两个电机按包络给最大扭矩伸腿，离地后收腿。测出实际能跳多高，作为 `h_feasible`；把这次跳跃的轨迹平滑后，作为参考的初始形状。

**第二步：由目标跳高 h\* 生成参考**（只有少数几个量）
| 阶段 | 判定 | 参考量 | 怎么定 |
|---|---|---|---|
| 下蹲 | 触发后 0–0.25 s | 腿长目标 l_min | 由可行性计算得到。下蹲越深，弹簧压缩越多，储能越多 |
| 蹬伸 | 下蹲结束到两轮离地 | 离地时竖直速度 ≥ `v_rel = √(2g·Δh)`，Δh 是离地后质心还要上升的高度 | 用单侧奖励：超过 v_rel 不扣分（可以跳得更高），不够才扣分 |
| 腾空 | 两轮离地（用 SCUT 的 airborne 判定） | 腿长目标 l_tuck | 收腿是为了离地间隙更大，l_tuck 取能收到的最短腿长再加一点余量 |
| 着地准备 | 竖直速度 < 0，且由高度推算出离落地不到 0.1 s | 腿长目标 l_land（略伸腿，为缓冲留出行程） | l_land ≈ l_stand + 2–3 cm |
| 缓冲 | 两轮触地之后 0.3 s | 不跟踪腿长，只惩罚冲击 | 让策略自己决定怎么缓冲 |

阶段切换用接触事件判定，不用固定时间，因为实际离地和落地时刻会变。相位 φ 只作为观测输入。机身高度曲线**不**作为跟踪目标，只在最高点结算一次结果奖励。

**第三步：奖励分成三类。结果奖励占主导，引导奖励只用来帮助探索，约束项保证安全。**
| 类别 | 窗口 | 项 | 权重（起点） | 来源 |

**第四步：课程和权重调度**
- **目标跳高课程：** h\* 从 0.10 m 开始，分 5 档升到 `h_feasible`，用 §5.9 的按回报采样。
- **引导权重下调：** 某一档跳高的成功率超过 70% 后，这一档的引导项权重在 2000 轮内从 1 倍线性降到 0.3 倍，并保留 0.3 倍的下限 [判]。这样策略先按参考学会基本动作，再按结果奖励去优化细节，可以偏离参考，比如下蹲得更深或者发力时机不同。
  - SCUT 反对的是"辅助力退火"，因为它改变了仿真动力学。这里下调的是奖励权重，动力学没有变，所以不存在那个问题。但最优解会随权重变化而移动，每次下调后都要在固定评测集上确认成功率没有下降。
- **σ 先宽后紧**（SCUT 的方法）：第一阶段 σ 取宽，先学会下蹲、蹬伸、收腿这套定性动作；第二阶段再收紧。
- 星云的跳跃奖励大多是结果型的（flight、积分高度、leg_tuck、takeoff_extend），已经在实车上跳到约 45 cm，说明"结果为主、少量引导"的组合是可行的。
**PD：** Kp 从 20 开始试，往 6–10 降（星云最终用 6/0.5）；轮扭矩 ±4.0 Nm（按 15.76:1 减速箱，见 §5.4）。
**通过标准：** 各档跳高的成功率达标，落地后不倒；每档实测跳高与目标误差 < 5 cm [判]。星云用 300 N 弹簧跳到约 45 cm（README）。

**跳隧道（必须项）[判]**
2027 规则把飞坡改成了隧道，可以"跨越"（从上方跳过去），获得 25% 防御增益，持续 30 s；条件是 3 s 内按顺序检测到入口和出口的场地交互卡（前瞻手册表 3-1）。**只做"整体跳过隧道、在隧道另一侧落地"，不做"落到隧道顶面"**：隧道太窄，落在顶面上容易摔倒，位置也不好。隧道的具体尺寸要等正式规则公布，所以先把设计做成参数化，尺寸出来后直接代入：
**正式规则里的隧道尺寸**（《RoboMaster 2027 机甲大师超级对抗赛比赛规则手册 V1.0.0（20261015）》§4.4.2，图 4-38 远高地隧道示意图）。下表是我对图的理解，**已经和你确认过**（2026-11-08）：
| 量 | 数值 | 我的理解 |
|---|---|---|
| 车道宽度 | 800 mm | 两侧护栏之间的通道宽度 |
| 隧道总长 | 2900 mm | 带两侧护栏的路段长度 |
| 横梁（金属板）沿行进方向的长度 | **350 mm** | 横跨车道的那块板，`L_t = 0.35 m`；它的起点距离路段一端 1350 mm |
| 侧视图标注 | 200 / 250 / 270 mm（以地面 G 为基准） | 两侧护栏高 200 mm；横梁下沿 250 mm（"穿越"时能通过的净空）；**横梁上表面 270 mm**，即 `H_t = 0.27 m` |

- **"穿越"要求整车（含云台）高度低于约 250 mm**，步兵带云台基本做不到，所以只考虑"跨越"，也就是跳过横梁。
- **触发条件**（规则 §5.6.4.5 和表 5-27）：3 s 内按顺序检测到隧道一端和另一端的场地交互模块卡，途中不能检测到其他卡，获得 25% 防御增益，持续 30 s；场上每方有 9 处隧道增益点。这意味着整个跳跃加落地要在 3 s 内完成，并且不能经过隧道内部的卡。
- **车道两侧有 200 mm 高的护栏、宽度只有 800 mm**：起跳前车身必须对正车道，空中不能有明显的偏航或侧移，否则会撞护栏。训练时要加偏航和侧向速度的约束，并且在仿真里把护栏建出来。

**由尺寸推算出的能力要求**（[判]，用你的实际几何代入）：
- **竖直方向：** 轮子最低点要高过横梁上表面并留出余量：`z_轮底,最高点 ≥ 0.27 + 0.03 = 0.30 m`。腾空时收腿能把轮子相对机身抬高 `Δl = l_stand − l_tuck`，所以机身质心需要上升的高度约为 `0.30 − Δl`（站立时轮底在地面上，高度为 0）。
- **水平方向：** 两个轮子左右并排，在轮底高于 0.30 m 的那段时间里，要水平飞过 `横梁长度 + 轮子直径 + 余量 ≈ 0.35 + 2r + 0.10 m`（r = 6 cm 时约 0.57 m）。轮底高于 0.30 m 的时间是 `t = 2·√(2·(z_轮底,最高点 − 0.30)/g)`，因此需要的前进速度是 `v_x ≥ 0.57 / t`。
  - 例子：轮底最高点到 0.40 m 时，t ≈ 0.29 s，需要 v_x ≥ 2.0 m/s；到 0.45 m 时，t ≈ 0.35 s，需要 v_x ≥ 1.6 m/s；到 0.50 m 时，t ≈ 0.40 s，需要 v_x ≥ 1.4 m/s。
  - 星云用 300 N 弹簧跳到约 45 cm（README 没说明是机身还是轮子的高度），你的弹簧是 450 N，量级上是有希望的。**结论以满力矩蹬伸脚本测出来的能力包络图为准。**
- **机身限制**（制作规范 S72，表 2-7）：步兵最大重量 28 kg（含电池和裁判系统），最大伸展尺寸 800 × 800 × 800 mm。跳跃时伸腿不能超过 800 mm 的高度限制，可行性计算里 `l_max` 要满足这一点。

1. **任务定义：** 行进跳（有前进速度的跳跃），让机身和轮子在空中整体越过一个高 `H_t`、长 `L_t` 的障碍，**在障碍后方的地面上落地**并恢复行驶。
2. **可行性计算，在第一步的基础上加入水平方向：**
   - 竖直方向：离地后质心要上升到能让轮子最低点高过 `H_t` 加余量（收腿能增加离地间隙），由此得到所需的 `v_z`；
   - 水平方向：腾空时间 `t_f ≈ 2·v_z/g`，水平飞行距离 `≈ v_x · t_f`，要大于 `L_t` 加上机身长度和余量，由此得到所需的助跑速度 `v_x`；
   - 检查：`v_z` 不超过 `h_feasible` 对应的离地速度；`v_x` 在 P1 能稳定行驶的速度范围内，而且轮子在起跳前的蹬伸阶段能保持住这个速度。
   - **满力矩蹬伸脚本加上前进速度**，直接在仿真里测出不同助跑速度下的最大跳高和跳远，画成"能力包络图"，再和隧道尺寸对比。
3. **训练：**
   - 地形：在 P3 的训练场景里按图 4-38 建一个隧道模型：800 mm 宽的车道、两侧 200 mm 高的护栏、350 mm 长的横梁，横梁上表面高 270 mm（随机 ±1 cm，覆盖场地的制造误差）；横梁放在机器人前方，到达前的助跑距离随机，起始时的偏航误差也随机（±5°），让策略学会在车道里对正；
   - 触发：操作手在起跳距离附近按下跳跃键。星云在起跳前用 TOF 测距，距离 < 0.9 m 才放行 [码 FD-deploy `chassis.cpp:1899-1988`]。可以加一个前向测距，把"到障碍的距离"作为一个可选观测，或者只用来限制什么时候允许触发；要观测的话先在模式位里预留，并在实车上确认测距可靠 [判]；
   - 奖励：在本节第三步的基础上增加两项：一是"越过障碍"的结果奖励，条件是两个轮心都越过障碍的后边缘、落在后方地面上，并且落地后 1 s 内保持平稳；二是**接触障碍的惩罚**，任何部位碰到障碍的顶面或侧面都扣分，碰到顶面的扣得更重。这样策略不会学会"先落到顶面再下去"这种取巧的走法。参考量里的 `Δh` 和 `v_x` 由第 2 点的可行性计算给出；
   - 课程：横梁高度从 0.10 m 开始，逐渐升到 0.27 m，最后到 0.30 m（多留 3 cm 余量），用 §5.9 的按回报采样按横梁高度分档。护栏从一开始就要有。
4. **机构的预案：** 如果能力包络图显示跳不过去，立刻反馈给机械组。可以调整的方向有：更强的气弹簧（同时检查站立时电机的静态负载）、加长蹬伸行程、减轻机身、调整轮子减速比（影响助跑速度）。这类改动越早越好。

### 6.7 阶段 J：策略切换和整车联调
- **H7 状态机：**
  - 默认运行 P1；
  - 小陀螺键：机身稳定时切到 P2；松开后把 ωz 斜坡降到 0，再切回 P1；
  - 跳跃键：机身稳定时切到 P3，并触发 flag；φ 到 1 且姿态稳定后切回 P1（星云是跳 480 ms 后切到 MiniRecover，并保持 1 s）；
  - 倾角超过阈值时，任何状态都切到 R，满足接管条件后再交给 P1。
- **切换时：** 清空上一帧动作（星云还清空历史）[码 FD-deploy `chassis.cpp:1992-1996`]；同时把 PD 目标值和 Kp/Kd 在 50–100 ms 内线性过渡到新策略的值 [判]。
- **训练时就为切换做准备：** 从 P2、P3 训练的 rollout 末尾截取状态（残余转速、刚落地），加入 P1 的重置分布；P2、P3 的初始状态则从 P1 的行驶状态里采样。
- **整车联调：** 云台和发射机构工作时的反作用力、裁判系统的功率上限、超级电容的放电曲线，都要在随机化或功率控制层里覆盖到。

## 7. 训练出来的网络是什么样：规模、输入输出、能否直接输出力矩

### 7.1 网络规模
**主方案：每个策略一个 MLP，结构 35 → 256 → 128 → 64 → 6。** 共 3 个隐藏层，ELU 激活，输出层是线性层，没有 tanh。
| 层 | 参数量 |
|---|---|
| 35 → 256 | 9,216 |
| 256 → 128 | 32,896 |
| 128 → 64 | 8,256 |
| 64 → 6 | 390 |
| **合计** | **50,758 ≈ 5.1 万** |

- FP32 权重约 **198 KB**。SCUT 导出的 256 宽 ONNX 是 204 KB，和这个数吻合 [码 SCUT 报告第 12 条]。激活缓冲区不到 2 KB。
- 3 个策略合计约 600 KB。**达妙板 DM-MC-Board02 的芯片是 STM32H723VGT6，不是 H743**（见 §13）：片上 Flash 1 MB，RAM 564 KB，主频 550 MHz。星云在同样 1 MB 的 Flash 里放了约 5 个 155 KB 的模型。按下面的顺序决定：
  1. 编译后看 `.map` 文件里固件代码的大小。如果代码加 600 KB 权重不超过 1 MB 的约 90%，3 个策略都用 256 宽；
  2. 超出时，P2、P3 改用轻量版（128 宽）：P1 198 KB + 2 × 59 KB ≈ 316 KB；
  3. 还不够的话，把权重放进板载 8 Mb QSPI Flash（W25Q64JV，1 MB），用内存映射方式读取。会慢一些，要实测推理时间 [核]。
- **轻量版：** 35 → 128 → 64 → 32 → 6，约 1.5 万参数、59 KB（SCUT 预训练里有这一档，62 KB）。
- **推理时间：** 星云 3.9 万参数的模型在 H7 上用 CubeAI 实测 0.6 ms。5.1 万参数估计在 1 ms 以内，按 100 Hz 推理计算，CPU 占用约 10% [判，以实测为准]。
- **为什么不用更大的网络：** SMW 的 SuperMimic 策略约 700 万参数（27.7 MB），H7 放不下。轮腿运动控制用这个量级的小 MLP 就够了，两支队伍都已经在实车上验证过。

### 7.2 可选：v2 历史估计器（零速定点或台阶表现不够时再加）
- 结构照星云：5 帧历史（5 × 35 = 175 维）→ 128 → 64 → 5，输出 3 维线速度估计加 2 维轮子接触概率。这部分**用监督学习训练**：线速度用 MSE，接触用 BCE，标签来自仿真真值，做法和 Flamingo SRM、星云 encoder 相同 [码 FD-train `ppo.py:263-283`，FLM `srmppo.py:245-300`]。
- 估计结果拼进 actor 输入，actor 改为 40 → 256 → 128 → 64 → 6。估计器约 3.1 万参数，合计约 8.3 万参数，约 330 KB。
- 导出成一个 ONNX，带两个输入 `obs[1,35]` 和 `obs_history[1,175]`，形式和星云一样（`obs[1,25]` 加 `obs_history[1,125]`）[码 FD 报告第 14 条]。
- SCUT 在实车上发现：没有历史信息的 MLP 在零速定点上较差，用 H7 推理降低延迟后有改善。所以 v1 先不加估计器，等实车数据说明需要时再加。

### 7.3 输入和输出
- **输入：** float32[1, 35]，内容见 §5.2 的表格（指令 3 + 腿高 1 + 角速度 3 + 重力 3 + 关节位置 6 + 关节速度 6 + 上一帧动作 6 + 模式位 7）。
- **输出：** float32[1, 6]：
  - `a[0:4]`：4 个髋电机的位置目标偏移，`q_ref = q_default + 0.5·a`，单位 rad；
  - `a[4:6]`：2 个轮子的速度目标，`ω_ref = 10·a`，单位 rad/s。
  - 这 6 维的顺序是 articulation 的关节顺序，不是 CAN 通道顺序，固件里要用一张映射表转换。
- **H7 上的换算：** 动作 → PD → 力矩 → 安全仲裁和限幅 → CAN 下发。

### 7.4 能不能直接输出 6 个电机的力矩，不做五连杆解算？
**这里有两个问题，答案不同。**

**(1) 不经过五连杆解算：可以，而且推荐。**
- 训练时在仿真里保留真实闭链（§3.1），被驱动的关节就是 4 个髋电机本身。策略输出的就是电机目标，H7 上不需要任何串联到并联的力矩映射，SCUT 就是这样做的 [码 SCUT `env.py:2774-2779`：腿部动作直接作为 front1/rear1 关节的位置目标，没有虚拟腿这一层]。
- 星云走的是另一条路：训练用串联等效树，所以固件每 2 ms 都要做一次五连杆正解和雅可比映射（`chassis.cpp:1538-1619`）。我们不需要这一步。
- **但五连杆正解在 H7 上仍然要写**，只是不在策略回路里。它用在三个地方：
  - 安全检查：腿长范围、奇异位形；
  - 手写恢复控制器 R（基于 VMC 的腿长和腿角）；
  - 跳跃、台阶阶段判断和日志记录。

**(2) 直接输出力矩，不用 PD：不建议。** 理由如下 [判，依据来自开源经验]：
1. **频率不够。** 策略 100 Hz 推理，力矩要保持 10 ms 不变，两次推理之间没有任何反馈，刚度只能靠策略自己维持。要改成 500 Hz 推理，训练和推理的开销都会增加约 5 倍，探索也更难。
2. **对延迟更敏感。** PD 内环每 2 ms 就会对偏差做出反应；直接输出力矩时，所有反馈都要经过 6–16 ms 的观测延迟。
3. **电机建模误差会直接暴露。** SCUT 发现，剧烈工况下实车电机的力矩响应有滞后、超调和抖动；用 PD 目标时，这部分误差有一部分会被内环吸收。
4. **安全。** 位置目标是有界的，训练初期动作带噪声时，PD 会限制动作幅度；直接输出力矩时，噪声就是力矩，动作会很猛。我看过的开源轮腿（SCUT、星云、Flamingo）全都用 PD 目标。
5. **想要接近力矩控制的效果，可以降低 Kp。** Kp 很低时，位置目标实际上相当于力矩指令（BeyondMimic 和 SuperMimic 附录 A 的说法），P3 跳跃用 Kp 6 正是这个用途。轮子的 `τ = 0.2·(ω_ref − ω)` 本身就是"带速度反馈的力矩指令"。

## 8. sim2sim（MuJoCo，每个策略上车前都要过）
1. **模型：** 用 §3.3 生成的 MJCF。在 XML 里显式写上 `timestep`，和训练的物理步长一致。
2. **脚本：** 参考 SMW 的 `mujoco_env.py`（弹簧、PD、状态读取）和 `play_mujoco.py`（键盘/手柄遥控，可以直接拿来做操作手训练）。要严格按 H7 固件的流程写：
   - 每 5 个物理步推理一次；
   - 观测的构造顺序、缩放和裁剪都和固件一致；
   - 指令斜率限制和固件一致；
   - 延迟取实测的中心值，另外跑一组取极端值；
   - 力矩在电机侧限幅。
3. **开环对比：** 用 `verify_against_isaac.py` 回放 Isaac 录下的轨迹，比较关节、轮心、机身姿态。
4. **闭环评测：** 用 §5.12 的评测集，同一个 ONNX 在 Isaac 和 MuJoCo 中各跑一遍，比较每组的失败数和跟踪误差。SMW 的经验可以作为基准：PPO 策略在 MuJoCo 中速度跟踪误差约 0.03–0.04 m/s [码 SMW `play_mujoco.py:166`]。
5. **数值一致性：** 准备 100 组固定输入，比较 PyTorch、ONNX Runtime、CubeAI 生成的 C 代码（在 PC 上运行）三者的输出，最大误差小于 1e-4。这组数据就是 golden vector，后面在 H7 上也要复用。
6. **没通过不要上车。** 排查顺序：先查接口是否对齐（四元数顺序、缩放、关节顺序、正负号、轮子位置是否给了 0），再查模型差异。

## 9. 部署到 H7（达妙板）

> **实现位置：** 固件基于队内框架 `control-2026`（`D:\Code-RM\github`），工作包见执行手册 §4.0 和 §4.4（FW0–FW6）。队内框架里已有 H723 的 ioc（配置为 480 MHz）、BMI088 + QuaternionEKF（1 kHz）、DM/DJI 电机驱动，以及和你们硬件相同的 sjtu 轮腿代码。下面各小节写的是"要做到什么"，在框架里"怎么改"见执行手册。

### 9.1 导出
1. 在 Isaac Lab 里运行 `play.py`，会导出 `exported/policy.onnx`，输入为 `obs [1,35]`，输出为 `actions [1,6]`，网络是 Gemm + Elu，没有归一化层 [码 SCUT `play.py:457-478`]。
2. 写一个 `policy_meta.yaml`，把所有和这个策略相关的参数放在一份文件里：obs_version、各项缩放、q_default、Kp/Kd、力矩限幅、动作缩放、模式位语义、关节映射表、弹簧参数。**固件里的策略参数表由脚本从这份 yaml 生成，不要手抄**。星云 README 里写弹簧 300 N，代码里补偿系数却是 370.1，就是多处手工维护造成的不一致 [码 FD 报告第 15 条]。

### 9.2 CubeMX / X-CUBE-AI 配置（星云踩过的坑，全部照做）
| # | 设置 | 不这样做的后果 |
|---|---|---|
| 1 | 选 FP32，不量化 | 量化误差会成为新的 sim2real gap；FP32 的推理时间已经够用 |
| 2 | **关闭 FPU 异常中断** | CubeAI 运行一段时间后会因为下溢、结果不精确进入异常 [码 FD-deploy `readme.md:275-310`] |
| 3 | 打开 CubeAI 面板时**不要接受时钟自动修复的弹窗**，每次重新生成代码后都检查时钟树 | 时钟被改掉（8.1.0 版本最严重） |
| 4 | 把 `syscalls.c` 改名为 `user_syscalls.c` 放到自己的目录 | 启用 CubeAI 后重新生成代码会删掉它 |
| 5 | DMA 发送前调用 `SCB_CleanDCache_by_Addr`，DMA 接收后做 Invalidate | 启用 CubeAI 会打开 D-Cache，DMA 会发送旧数据（星云的 UI 绘制因此出错） |
| 6 | 开启 CRC 时钟 | CubeAI 运行时库需要 CRC |
| 7 | 每个模型使用独立的**静态**激活缓冲区，4 字节对齐，控制循环里不使用 heap | 内存碎片和不确定的耗时 |
| 8 | 权重参数传 `nullptr`，使用生成代码里的权重 | — |
| 9 | 生成的代码和 CubeAI 的版本绑定，换版本后要整套重新生成 | 运行时库与生成代码不匹配 |
| 10 | 用 X-CUBE-AI 自带的两种验证（见下） | 数值不一致发现得太晚 |

**X-CUBE-AI 的两种验证是什么意思**（X-CUBE-AI 底层用 ST Edge AI Core，按钮名称和命令行参数因版本而异，以你安装的版本为准 [核]）：
- **Validate on desktop（在电脑上验证）：** 把 X-CUBE-AI 生成的 C 推理代码在电脑上编译运行，和原始 ONNX 用同一组输入各算一遍，比较输出，报告误差（例如 L2 误差、最大绝对误差）。这一步检查"模型转换成 C 代码后结果是否正确"，不需要板子。命令行对应 `stedgeai validate -m policy.onnx --target stm32h7`（主机模式）[核]。
- **Validate on target（在板子上验证）：** 先把一个专门的"验证固件"烧进达妙板，电脑通过串口（ST-Link 的虚拟串口，或 USB 转串口接到板上的 UART）把输入发给板子，板子上跑推理后再把结果传回电脑比较。同时会报告**实际推理耗时（CPU 周期数）**和 RAM/Flash 占用。这一步检查"在真实芯片上（FPU、Cache、编译选项都和实际一样）结果和耗时是否正确"。命令行对应加上 `--mode target -d serial:COMx` 这一类参数 [核]。
- **用法建议：** 两种验证都**传入你自己的 golden vector**（§8 第 5 条的 100 组输入），不要只用工具随机生成的输入，因为随机输入覆盖不到真实观测的取值范围。生成 CubeMX 工程时也可以选择 "Validation" 应用模板，它就是上面说的验证固件。验证通过后，再换成你自己的应用代码。
- 达妙板没有板载 ST-Link，要用外接 ST-Link 走 SWD 下载，再选一个 UART 接 USB 转串口做通讯。

### 9.3 任务和节拍
| 任务 | 频率 | 内容 |
|---|---|---|
| CAN 接收、IMU 读取 | 1 kHz 或中断触发 | 更新电机状态和姿态 |
| **控制任务** | **500 Hz（与训练的物理步长一致）** | 读取状态 → 五连杆正解（用于安全检查）→ PD → 安全仲裁 → 功率控制 → CAN 下发 |
| 策略任务 | 100 Hz（每 5 个控制周期一次） | 构造观测 → CubeAI 推理 → 检查输出 → 写动作双缓冲 |

- 推理放在控制任务之外，或者在控制任务里也行（1 ms 小于 2 ms 的控制周期，但比较接近，建议放到单独的低优先级任务里），但不能放进比 CAN 发送优先级更高的中断。
- **在训练里复现时序：** 观测在策略周期开始时采样，动作从下一个控制周期开始生效，这就是至少 1 步的动作延迟，训练中的延迟随机化要覆盖它。
- 星云的固件是 500 Hz 控制、100 Hz 推理，但训练用的是 200 Hz PD，两边频率不一致 [码 FD 报告]。我们训练和固件都用 500 Hz 物理/PD、100 Hz 推理，两边完全对应。

### 9.4 电机接口与单位换算
- **髋电机（8009P，手册 V1.3）：** 用 MIT 模式，只发力矩（手册说明 `kp = 0, kd = 0`，只给 `t_ff` 时就是力矩输出），PD 在 H7 上以 500 Hz 计算，这样和仿真里的 IdealPD 对应 [判]。星云也是固件算好力矩后下发。
  - **先在 DMTool 里改 PMAX/VMAX/TMAX，并且和队内驱动的宏保持一致。** MIT 帧里的位置、速度、力矩是定点数，分别按 ±PMAX、±VMAX、±TMAX 线性映射。8009P 出厂默认 TMAX 是 **±10 Nm**、VMAX 是 ±30 rad/s；队内框架 `dmmotor.h:26-31` 把 J8009P 写成了 PMAX 12.5、VMAX 45、TMAX 54（星云也用 54）。所以电机里要设成 **12.5 / 45 / 54**，或者改驱动的宏，两边必须一致。TMAX 54 时，12 位编码的分辨率约 0.026 Nm/LSB；实际输出由固件限幅在 ±40 Nm。
  - **反馈是问询式的：** 电机收到一帧控制指令才回一帧反馈。所以 500 Hz 控制就得到 500 Hz 反馈，H7 用最近一帧反馈构造观测。
  - **位置反馈：** 上电后输出轴角度限定在 [−π, π]（单圈绝对编码器，掉电不丢）。安装零点时要让髋关节的工作范围不跨越 ±π，否则会出现角度跳变。
  - **保护参数**（在 DMTool 里设置）：
    - 欠压阈值：手册要求不低于 15 V。6S 电池满电约 25.2 V，起跳时会瞬间压降，阈值和供电硬件要一起考虑；
    - 通讯丢失超时：建议 50–100 ms，H7 死机时电机会自己失能；
    - 过流系数：不超过 0.98；电机过温：不超过 100 °C。
  - CAN 是 1 Mbps 标准帧。每条腿一路 CAN：2 个 8009P（500 Hz 控制帧加反馈帧，约 2000 帧/s），加 1 个 C620（控制帧 500 帧/s，反馈默认 1 kHz），合计约 3500 帧/s，每路负载约 45% [判]。必要时可以用 RoboMaster Assistant 把 C620 的反馈频率降到 500 Hz，负载就会降到约 35%。
- **轮电机（M3508 + C620）：**
  - 控制帧 0x200 / 0x1FF，电流值 −16384 … 16384 对应 −20 … 20 A；
  - 反馈 ID 为 0x200 + 电调 ID，**默认 1 kHz**，内容是转子机械角度、**转子转速（rpm，电机侧）**、实际转矩电流、温度；
  - 轮速换算：`ω_wheel = rpm × 2π/60 / 15.76`（减速比 15.76）；
  - 力矩换算：`i = τ_wheel / (Kt_m × 15.76 × η)`，其中 `Kt_m ≈ 0.3 / (3591/187) ≈ 0.0156 N·m/A`（由手册的输出轴扭矩常数反推，已经含原减速箱效率）。η 的偏差靠 real2sim 时辨识出的力矩缩放系数来修正 [判]。
- **总线分配（按你们的实际方案）：** CAN1 接左腿（2 个 8009P + 左轮 C620），CAN2 接右腿（2 个 8009P + 右轮 C620），CAN3 接超级电容、裁判系统、双板通信等。策略都在底盘控制板上运行。
  - **小陀螺需要云台相对底盘的 yaw 角**（GM6020 的编码器）。如果是双板方案，并且 6020 接在云台板上，就要通过队内的 `can_comm` 把这个角度以不低于 100 Hz 的频率发给底盘板，并且计入观测延迟。
- **零点偏置：** 用一个可以复现的机械姿态作为标定零位（星云是导轮着地、两腿向后），在 SolidWorks 里量出这个姿态与策略零位之间的角度差。星云大腿约 ±0.2569 rad，小腿约 ±0.767 rad。**偏置只在读取编码器时换算一次**，后面所有代码都用策略零位下的角度 [码 FD-deploy `chassis.cpp:1686-1693`]。
- **方向和映射：** 每个电机单独检查正方向。推理顺序 ↔ CAN 通道用一张表映射（星云在 `calculateRLTorques` 的末尾做这一步）。
- **轮速：** 用电机反馈的速度，并且和训练中的速度来源保持一致（§5.2）。

### 9.5 策略表与切换
- 每个策略一行参数：`q_default`、Kp/Kd、轮扭矩限幅、动作缩放、指令缩放、模式位的写法，全部由 `policy_meta.yaml` 生成。
- 切换时清空上一帧动作和历史（如果用了估计器），同时让 PD 参数平滑过渡（§6.7）。
- 推理失败（返回的 batch 数不等于 1）或输出出现 NaN、越界时：动作清零，进入 Protect 状态，所有电机输出归零 [码 FD-deploy `chassis.cpp:2153-2158, 901-904`]。

### 9.6 功率控制
星云对轮子用 PowerLimiter 加 RLS 在线辨识功率模型；超级电容电量可信时，按电量在 30–128 W 之间插值功率上限 [码 FD-deploy `chassis.cpp:596-850`]。功率控制会在运行时压低轮扭矩，所以训练里要加"轮扭矩上限随机 ×0.7–1.0"（§5.7），否则策略在功率受限时会出现训练中没见过的情况。

### 9.7 安全仲裁（独立于网络）
- 力矩限幅链：PD 输出 → 电机侧限幅（髋 ±40 Nm 并带转速包络；轮 ±4.4 Nm，跳跃时 ±4.0 Nm）→ 功率控制 → 下发。
- 星云的保护逻辑可以参考：|pitch| > 1.4 rad 时只保留大腿速度 PI 刹车；任意一个轮电机离线就所有力矩置零 [码 FD-deploy `chassis.cpp:1393-1452`]。
- 加上：五连杆运动学检查（腿长越界、|det J| 接近 0）、遥控器丢失超过 100 ms、母线欠压、电机过温，任意一项触发都进入保护状态。

### 9.8 上车流程
1. golden vector 在 H7 上比对通过，并实测 WCET（最坏执行时间）。
2. 手动转动每个关节、倾斜机身，用串口打印观测向量，逐项检查正负号、零点和顺序。
3. 架空运行策略：腿部动作平稳，给小速度指令时轮子方向正确。
4. 吊带保护下落地：零指令站立 → 低速前后 → 转向 → 调高 → 手推抗扰。
5. 每次测试都录 H7 日志和视频，并把实车的指令序列放回 MuJoCo 回放，逐帧对比找差异（SCUT 的方法）。

## 11. 训练平台：4090、L40 还是 L40S？

**结论：用 RTX 4090。**

| | RTX 4090 | L40 | L40S |
|---|---|---|---|
| 架构 | Ada | Ada | Ada |
| 显存 | 24 GB GDDR6X | 48 GB GDDR6（ECC） | 48 GB GDDR6（ECC） |
| 显存带宽 | 约 1.0 TB/s | 约 0.86 TB/s | 约 0.86 TB/s |
| FP32 峰值 | 约 83 TFLOPS | 约 90 TFLOPS | 约 92 TFLOPS |
| 定位 | 消费级 | 数据中心（偏图形） | 数据中心（偏 AI + 图形） |

以上规格是我凭记忆写的，租用前请按 NVIDIA 官方规格核对 [核]。

**理由：**
1. **显存够用。** SCUT 在 16 GB 的 RTX 5070 Ti 上就能用 4096 个环境训练 [码 SCUT README]。你的 PPO 是小 MLP，显存主要用在 PhysX 的并行环境上，24 GB 有余量。SMW 跑 SuperMimic（网络很大）才用到 17.8 GB [码 SMW README]。
2. **速度差不多。** 小 MLP 的 PPO，瓶颈在 PhysX 仿真吞吐上，而不是 Tensor Core 算力。三张卡都是 Ada 架构，FP32 峰值差距在 10% 以内；4090 的显存带宽还更高。L40S 多出来的 AI 算力，PPO 基本用不上 [判]。
3. **租金差很多。** 国内平台上，L40/L40S 的单价通常比 4090 贵不少，具体看平台报价。按"达到同一个评测成功率要花多少钱"算，4090 最划算 [判]。
4. **软件兼容。** 三张卡都有 RT 核心，都在 Isaac Sim 的支持范围内；SCUT 和 SMW 都在 4090、5070 Ti 这类卡上验证过。

**什么时候选 L40S：**
- 想在一张卡上同时跑 2 个实验，或者环境数超过 8192 并且带高度扫描，24 GB 不够时；
- 4090 租不到时。
- 不管哪种情况，L40S 都比 L40 好（同价位时 L40S 频率更高）。

**也可以考虑 RTX 5090（32 GB）**：如果平台有这张卡、价格接近 4090，它更快，显存也更大；SCUT 的 Isaac Sim 5.1 + cu128 环境支持 50 系显卡。

**租用策略：** 先按小时租一台 4090，跑一遍 `Flat-v0`，记下吞吐（env-steps/s）和显存占用，再决定是否长租、是否需要第二张卡。不需要多卡训练：一个策略单卡几个小时就能出结果，多跑几个随机种子比一次用多卡更有价值。

### 13.2 M3508 轮电机 + C620 电调（手册 V1.0 / V1.01）
| 项 | 原装 P19（3591/187 ≈ 19.2） | **你的 15.76:1（估算 [判]）** | 星云的 16.33（对照） |
|---|---|---|---|
| 输出轴扭矩常数 | 0.3 N·m/A（手册） | ≈ 0.0156 × 15.76 ≈ 0.246 N·m/A | ≈ 0.255 N·m/A |
| C620 持续 20 A 对应的扭矩 | ≈ 6 Nm | **≈ 4.9 Nm** | ≈ 5.1 Nm（与星云"约 5 Nm 就失控"吻合） |
| 空载转速（24 V） | 482 rpm = 50 rad/s（手册） | ≈ 587 rpm = **61.5 rad/s** | ≈ 567 rpm = 59 rad/s |
| 轮半径 6 cm 时的空载线速度 | 3.0 m/s | 3.7 m/s | 3.6 m/s |
| 额定（最大持续）扭矩 | 3 Nm（手册） | ≈ 2.5 Nm | ≈ 2.6 Nm |

- **推导方法：** 电机侧扭矩常数 = 0.3 / 19.2 ≈ 0.0156 N·m/A（已含原减速箱效率）；电机空载转速 ≈ 482 × 19.2 ≈ 9256 rpm。换减速比时，扭矩按 N 成正比，转速按 1/N 成正比。新减速箱的效率未知，所以表里的值都要用"轮子堵转测力矩"和"空载测转速"实测确认。
- **对训练和部署的影响：**
  - 15.76:1 和星云的 16.33:1 很接近：可用轮扭矩约少 4%（4.9 对 5.1 Nm），最高速度约高 4%（61.5 对 59.4 rad/s）。星云的轮子相关经验基本可以直接参考；
  - 训练和固件的轮扭矩上限取 4.4 Nm（留 10% 余量），跳跃时取 4.0 Nm。
- 不要长时间超过额定扭矩：持续超过约 2.5 Nm 会发热，比赛中要靠功率控制和温度监控限制。
- C620 的反馈默认 1 kHz，内容为转子角度、转子转速（rpm）、转矩电流、温度；电机温度超过 125 °C 时会保护。
